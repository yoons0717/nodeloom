# Nodeloom 반응형 대응

기준: `apps/web` 현재 코드(M6, 2026-10-13, 재리뷰 반영). 원칙은 DECISIONS B-11(좁은 화면은 안내 + 읽기 전용)과 DESIGN.md(토큰만, 상태는 Badge + 글리프)를 따른다.

숫자는 코드의 고정 폭(Tailwind 클래스)을 더해 계산했다. 실제 화면에서 잰 값이 아니다. 사이드바 폭은 접힘을 직접 고른 적이 없는 기본값 기준이다.

---

## 1. 지금 상태

나누는 기준은 **md(768px) 하나**뿐이다.

| 화면 | md 미만 | md 이상 |
|---|---|---|
| 사이드바 `sidebar-shell.tsx` | 숨김. 머리말의 메뉴 버튼으로 왼쪽 드로어 | 240px, 접으면 56px. 에디터에서는 기본으로 접힘 |
| 머리말 `page-header.tsx` | 메뉴 버튼이 보이고, "맥락 /"을 숨김 | 메뉴 버튼 없음, "맥락 / 제목" |

## 2. 문제

### R1. 768~1279px에서 캔버스가 너무 좁다
md를 넘으면 바로 데스크톱 배치가 되는데, 고정 폭 패널이 많다.

- **에디터:** 사이드바 56 + 팔레트 224 + 설정 패널 320 = 600px이 고정이다.
  - 768px → 캔버스 **168px**
  - 1024px → 424px
  - 1280px → 680px
- **실행 상세:** 실행 화면에서는 사이드바가 펼쳐진 채(240)라 240 + 384 = 624px이 고정이다.
  - 768px → 캔버스 **144px**
  - 1024px → 400px

iPad 세로(768~834)나 작은 노트북에서는 사실상 쓸 수 없다.

### R2. 폭으로 입력 방식을 짐작한다
`md:` 하나가 "넓다"와 "마우스가 있다"를 함께 뜻하고 있다. 넓은 터치 화면(태블릿)에서 이 가정이 깨진다.

- 목록의 삭제 버튼은 `md:opacity-0` + `group-hover:opacity-100`이다. Tailwind v4의 `hover:`는 hover가 되는 기기에서만 동작한다. 그래서 태블릿에서는 버튼이 **안 보인 채로 남는다**. 포커스가 갈 때만 보인다.
- 노드 입출력의 탭과 복사 버튼은 `h-11 md:h-7`이다. 태블릿에서는 28px이 되어 손가락 기준(44px)보다 작다.
- 폭과 상관없이 작은 것도 있다.
  - 캔버스 도구 막대(되돌리기 포함): `canvas-controls.tsx`, 36px
  - 사이드바 항목과 아이콘 버튼: 32px
  - 실행 기록 필터 칩: 32px
  - 도움말 (?): 24px
  - 노드 카드 포트

### R3. 마우스를 올려야 보이는 정보
`title=` 속성은 터치와 키보드로는 볼 수 없다.

- **그래프 문제 배지** `editor.tsx` `GraphIssueBadge`: 문제 문구를 마우스를 올려야만 볼 수 있다. 화면 읽기 프로그램용 문구(aria-label)는 있지만 눈으로 볼 방법이 없다.
- **노드 카드 오류** `node-card.tsx`: 오류 문구가 `title`로만 있다.
- **실행 행 시각** `run-history.tsx`: 전체 날짜·시각이 `title`로만 있다. 이건 날짜 그룹 머리글이 있어 괜찮다.
- **저장 실패 사유** `save-controls.tsx` `SaveStatus`: 칩에는 짧게 "저장 실패"만 보이고, 긴 사유(예: 로그인 만료 안내)는 `title`과 화면 읽기 프로그램용 글자로만 있다. 이름 칸 오류는 칩 자리에 글자로 보이므로 문제가 아니다.

### R4. 실행 상세의 `h-[50vh]`
모바일 브라우저에서는 주소창이 나타났다 사라질 때마다 `vh`가 바뀌어 화면이 덜컹거린다. 바깥 틀은 `h-dvh`를 쓰는데 여기만 `vh`라서 기준도 섞여 있다.

### R5. 아주 좁은 폭에서 실행 행
375px 기준으로 방식이 들어갈 칸이 약 60px 남는다. 375에서 바깥 여백 32와 행 여백 32를 빼고, 고정 열(배지·시각·화살표) 144, 열 사이 48, 걸린 시간 약 50을 빼면 그 정도다.

- "워크플로 이름 · 방식"이 들어가는 **모든 실행**에서는 워크플로 이름이 거의 다 잘린다.
- 320px에서는 더 줄어든다.

### R6. 좁은 화면 에디터 안내가 막다른 곳
안내 화면에는 "실행 기록 보기"만 있다. **설정**(실패하면 실행)은 읽기·쓰기 화면이라 좁은 화면에서도 쓸 수 있는데, 거기로 가는 길이 없다. 메뉴 버튼으로 드로어를 열면 갈 수는 있다.

### R7. 노치·홈 바 영역
`viewport-fit=cover`와 `env(safe-area-inset-*)` 처리가 없다. 지금은 브라우저가 기본 여백을 두므로 깨지지는 않는다. 다만 홈 화면에 추가(PWA)하면 드로어와 하단 여백이 겹칠 수 있다. 우선순위는 낮다.

### R8. 좁은 화면에서도 에디터가 통째로 그려진다
`workflow-editor.tsx`는 안내 화면과 에디터를 둘 다 그리고, CSS(`md:hidden` / `hidden md:contents`)로 하나만 보여 준다. 그래서 휴대폰에서도 다음이 모두 돈다.

- React Flow, 단축키, ⌘S, 저장 전 확인(`beforeunload`, 링크 가로채기)
- 크기가 0인 상자 안에서 React Flow가 처음 그리기(크기 경고가 날 수 있음)

보이지 않는 편집 화면이 사이드바 링크를 가로채 "저장하지 않은 변경"을 물을 일은 거의 없다. 다만 내려받고 실행하는 양은 그대로다.

### R9. 노드 추가가 HTML 끌어다 놓기뿐이다
`palette.tsx`는 `draggable` + `onDragStart`, `canvas.tsx`는 `onDrop`(dataTransfer)을 쓴다. 이 방식은 터치 기기에서 브라우저마다 동작이 달라 믿기 어렵다. 그래서 태블릿 편집을 하려면 **누르면 추가**하는 길이 따로 있어야 한다.

## 3. 원칙

1. **폭과 입력 방식을 따로 본다.**
   - 폭(배치)은 `md` / `lg` / `xl`로 나눈다.
   - 입력 방식(hover, 누르는 크기)은 Tailwind의 `pointer-coarse:` / `pointer-fine:`로 나눈다. 이 변형은 v4.1부터 있다. package.json은 `^4`이므로 잠금 파일에서 실제 버전을 확인한다. 4.0이면 `@custom-variant`로 직접 정의한다.
   - `md:`를 터치 판정에 쓰지 않는다.
2. **편집은 넓은 화면, 읽기는 모든 화면.** B-11을 유지한다. md 미만은 읽기 전용, md 이상에서만 편집한다.
3. **캔버스는 최소 480px.** 고정 패널은 그 폭이 지켜질 때만 나란히 두고, 아니면 겹쳐 띄운다(오버레이).
4. **hover로만 볼 수 있는 정보는 없다.** 같은 내용을 누르거나 포커스해도 볼 수 있어야 한다.
5. **높이는 `dvh`/`svh`만 쓴다.** `vh`는 쓰지 않는다.

### 폭 단계

| 단계 | 폭 | 이름 | 에디터 |
|---|---|---|---|
| base | < 768 | 휴대폰 | 안내(읽기 전용) |
| md | 768 – 1023 | 태블릿 · 좁은 창 | **간단 배치**(아래 4-3) |
| lg | 1024 – 1279 | 작은 노트북 | 간단 배치 |
| xl | ≥ 1280 | 데스크톱 | 지금 배치(3열) |

lg와 md를 나눈 이유는 실행 상세 때문이다(4-4).

## 4. 화면별 규칙

### 4-1. 사이드바 (`sidebar-shell.tsx`, `app-sidebar.tsx`)

| 폭 | 규칙 |
|---|---|
| base | 지금처럼 드로어 |
| md – lg | **항상 56px 레일.** 펼치기를 누르면 240px로 캔버스 **위에 겹쳐** 열고(밀어내지 않음), 바깥을 누르면 닫는다. 접힘 저장값은 무시한다 |
| xl | 지금처럼(저장값을 따르고, 에디터에서는 기본으로 접힘) |

- `resolveCollapsed`에 폭 조건을 더한다. 처음 그릴 때 어긋나지 않도록 폭 판단은 CSS로 하고(`xl:` 클래스로 240 / 56 전환), JS는 펼침 상태만 관리한다.
- 드로어와 겹쳐 연 사이드바 모두 `env(safe-area-inset-left)`만큼 안쪽 여백을 둔다(R7).

### 4-2. 머리말 (`page-header.tsx`, 에디터 `TopBar`)

| 폭 | 규칙 |
|---|---|
| base | 메뉴 버튼, 화면 이름만, 동작 버튼은 아이콘이나 짧은 글자(예: 실행 상세는 지금처럼 "에디터") |
| md 이상 | "맥락 / 제목" |
| 에디터 md – lg | 이름 칸 `max-w-72` → `max-w-48`. 저장 상태 칩은 글리프만 남기고 글자는 숨긴다(`xl:inline`) |

### 4-3. 에디터 (`editor.tsx`, `palette.tsx`, `settings-panel.tsx`)

| 폭 | 팔레트 | 설정 패널 | 캔버스(사이드바 56 포함) |
|---|---|---|---|
| base | – | – | 안내 화면 |
| md – lg | **56px 레일**: 노드 글리프만 보이고, 누르면 팝오버로 이름·설명·(?)·**"캔버스에 추가"**가 나온다. 추가하면 지금 보이는 영역 가운데에 놓는다(R9). 끌어다 놓기는 마우스에서만 쓴다 | **오른쪽에서 겹쳐 나오는 패널**(320px, 캔버스 위). 노드를 고르면 열리고, 선택을 풀거나 Esc를 누르면 닫는다. 캔버스를 밀어내지 않는다 | 768 → 656, 1024 → 912 |
| xl | 지금(224) | 지금(320, 나란히) | 1280 → 680 |

- 겹쳐 나오는 설정 패널은 `--overlay` 배경과 그림자를 쓴다. 열려 있는 동안에도 캔버스는 움직일 수 있다(모달 아님).
- 도움말 팝오버(`help.tsx`, `w-[440px]`)는 설정 패널 왼쪽으로 연다(`sideOffset` 12). 768px에서는 왼쪽 공간이 768 − 320 − 12 − 8(`collisionPadding`) = 428px이라 **440px가 들어가지 않는다.** 폭을 `w-[min(440px,var(--available-width))]`로 바꾼다. 높이는 이미 `--available-height`를 쓰므로 폭도 같은 방식으로 맞춘다.
- 실행 토스트(`run-controls.tsx`, `w-72`, 오른쪽 정렬)는 그대로 둔다.
- 안내 화면(R6)에는 "실행 기록 보기"와 **"설정"** 링크를 두 버튼으로 둔다. 버튼 높이는 44px로 한다.
- md 미만에서는 `<Editor>`를 **아예 그리지 않는다**(R8). 처음 그릴 때 어긋나지 않게 하려면, 안내 화면은 CSS로 계속 보여 주고 에디터만 마운트 뒤 `matchMedia('(min-width: 768px)')`가 참일 때 그린다. 그 전에는 빈 자리를 보여 준다.

### 4-4. 실행 상세 (`run-detail.tsx`)

| 폭 | 배치 |
|---|---|
| base – md | 위아래로 쌓는다. 캔버스는 `h-[45svh] min-h-64`, 패널은 그 아래. 노드를 고르면 패널 맨 위로 스크롤 |
| lg | 나란히. 패널은 `lg:w-80`(320). 사이드바는 56 레일이라 캔버스는 1024 → 648 |
| xl | 나란히. 패널은 `xl:w-96`(384) |

- `md:flex-row` → `lg:flex-row`로 바꾼다(R1, R4).
- 위아래로 쌓을 때 실행 순서(`run-timeline.tsx`)는 노드가 8개를 넘으면 기본으로 접힌다. 지금 규칙을 그대로 둔다.

### 4-5. 실행 기록 · 모든 실행 (`run-history.tsx`)

| 폭 | 행 |
|---|---|
| base (< 640) | **두 줄.** 1줄: 배지 · 시각 · 걸린 시간 · ›. 2줄: 워크플로 이름(모든 실행일 때) · 방식, 오류는 그 아래 |
| sm 이상 | 지금 grid 한 줄 |

- 필터 칩은 지금처럼 줄바꿈하고, `pointer-coarse:h-11`을 붙인다.

### 4-6. 워크플로 목록 (`(app)/page.tsx`)

- 삭제 버튼 숨김 조건을 `md:opacity-0`에서 `md:pointer-fine:opacity-0`으로 바꾼다(R2). 터치 기기에서는 폭과 상관없이 항상 보인다.
- 나머지는 지금 그대로 둔다.

### 4-7. 노드 입출력 · JSON (`node-run-panel.tsx`, `json-view.tsx`)

- 높이를 `h-11 md:h-7`에서 `h-7 pointer-coarse:h-11`로 바꾼다.
- JSON 값 줄(누르면 식 경로 선택)은 `pointer-coarse:py-1`로 누르는 영역을 키운다.

## 5. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 누르는 크기 | `pointer-coarse` 기기에서 최소 44×44. 보이는 크기는 작게 두고 `after:` 가상 요소로 영역만 넓혀도 된다(포트와 같은 방식) |
| hover 정보 | `title=`은 보조로만 쓴다. 문제 배지와 노드 오류는 `Tooltip`(포커스로도 열림)으로 바꾸고, 터치에서는 누르면 팝오버로 연다(R3) |
| 숨김 동작 | hover 때만 보이는 버튼은 `pointer-fine:`에서만 숨긴다 |
| 높이 | 화면 틀은 `h-dvh`, 일부 영역은 `svh`. `vh`는 쓰지 않는다 |
| 겹쳐 띄우기 | 드로어·사이드바·설정 패널은 Esc로 닫고, 포커스를 가두고(드로어만), 닫히면 연 버튼으로 포커스를 돌려준다 |
| 안전 영역 | `layout.tsx` viewport에 `viewportFit: 'cover'`를 두고, 드로어와 화면 아래 고정 요소에 `env(safe-area-inset-*)` 여백을 둔다 |
| 확대 | `maximum-scale`로 막지 않는다. iOS는 16px보다 작은 입력 칸에 포커스하면 화면을 확대한다. 지금 입력 칸(`control-styles.ts` `text-sm` 14px)과 사이드바 검색(13px)이 해당된다. 둘 다 `pointer-coarse:text-base`를 붙인다. 휴대폰에서 실제로 쓰는 입력 칸은 드로어 안 검색, 로그인, 설정 화면이다 |

## 6. 작업 순서

각 단계는 따로 병합할 수 있다.

1. **입력 방식 분리(R2, R3).** 크기 변화는 없고 위험이 가장 작다.
   - `md:opacity-0` → `md:pointer-fine:opacity-0`
   - `md:h-7` → `pointer-coarse:h-11`
   - title → Tooltip
   - 입력 칸 16px(5장 "확대")
   - 좁은 화면에서 에디터 그리지 않기(R8)
2. **높이와 실행 상세(R1 일부, R4).** `vh` → `svh`, `md:flex-row` → `lg:flex-row`, 패널 `lg:w-80 xl:w-96`.
3. **사이드바 md–lg 레일 + 겹쳐 열기.**
4. **에디터 간단 배치.** 팔레트 레일과 누르면 추가(R9), 겹쳐 나오는 설정 패널, 도움말 팝오버 폭. 작업이 가장 크다.
5. **실행 행 두 줄(R5), 안내 화면 링크(R6), 안전 영역(R7).**

## 7. 확인

- 폭: **375 · 768 · 1024 · 1280 · 1440**. 화면마다 캔버스 폭이 480 이상인지 본다.
- 입력: 개발자 도구에서 터치 흉내 켜기 + 실제 iPad 세로. 삭제 버튼이 보이는지, 누르는 영역이 44px인지 본다.
- 키보드만으로: 겹쳐 연 사이드바와 설정 패널을 Esc로 닫고, 포커스가 돌아오는지 본다.
- 휴대폰 실기기: 주소창이 접혔다 펴질 때 실행 상세가 덜컹거리지 않는지 본다.
- e2e에 768px 시나리오를 하나 추가한다. "노드 선택 → 설정 패널이 겹쳐 열림 → Esc로 닫힘".
