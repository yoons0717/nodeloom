# 백로그

지금은 하지 않기로 한 아이디어. 한 줄씩.

- 다중 사용자 확장: 가입, 사용자별 소유권 검사(인가), 사용자 격리 (주제 2-1에서 MVP는 관리자 1명 로그인으로 결정)
- 시크릿 저장소(화면 입력 + DB 암호화 저장, 사용자별): 다중 사용자 확장과 함께 진행. `$secrets.NAME` 참조 문법은 그대로 두고 값을 가져오는 곳만 교체 (주제 2-2)
- 워크플로우 버전 관리: 불변 버전 테이블, 버전 목록·복원 화면, 낙관적 락(409). MVP는 실행 시점 그래프 스냅샷만 저장 (주제 2-3)
- 코드 노드(JavaScript): 실사용 흐름에서 표현식으로 안 되는 경우가 실제로 생기면 재검토. 격리 실행 방식이 선결 과제 (주제 3-1)
- 표현식 쉬운 층 UI: 앞 노드 출력에서 클릭해 경로 넣기, Condition 폼(값 / 연산자 / 값 → 내부적으로 JSONata로 변환) (주제 3-2)
- 노드 참조 키를 바꿀 때 그 키를 쓰는 표현식을 자동으로 고쳐 주기. MVP는 "없는 키 참조" 검증 오류만 표시 (주제 3-4)
- 워크플로우(Trigger)별 시간대 지정: 다중 사용자 확장과 함께. MVP는 `APP_TIMEZONE` 하나 (주제 3-5)
- 성능 회귀 감시: CI에서 번들 크기, Lighthouse 기준 초과 시 실패 처리 (주제 5-3)
- 줌 배율별 노드 단순화(저배율에서 제목만 표시) (주제 5)
- 표현식 미리보기 입력 지연 개선(디바운스, Web Worker, INP 측정) (주제 5)
- 실행 기록 목록 성능: DB 인덱스 + 커서 페이지네이션 + 목록 가상화 (주제 5)
- 상태 저장 노드("지난번 값" 읽기·쓰기): 실사용 흐름이 "변화 감지" 형태로 정해지면 재검토 (주제 3-1)
- 데모 서버 자동 초기화(1시간마다 pg-boss cron으로 시드 재적용 + 안내 배너) (주제 6-5)
- 데모 예제 워크플로우 잠금 + 복제해서 편집 (주제 6-5)
- 합류 노드 방식 선택(모두 기다림 / 하나라도), n8n Merge 노드 방식. MVP는 "하나라도 성공하면 실행" 고정 (주제 7-2)
- 노드별 오류 출력 포트(실패 시 같은 흐름 안에서 분기). MVP는 "실패 시 다른 워크플로우 실행" (주제 7-4)
- API와 실행 워커 프로세스 분리(같은 코드, 진입점 2개). MVP는 한 프로세스 (주제 7-6)
- 노드 하나만 테스트 실행("이 노드까지 실행"). MVP 2차는 마지막 실행 데이터로 미리보기 (리뷰 A-5)
- HTTP 요청 멱등 키 헤더 지원(재개 시 중복 요청 완화). MVP는 "최소 한 번 실행" 한계 명시 (리뷰 B-2)
- 모바일 편집 지원. MVP는 좁은 화면에서 안내 + 읽기 전용 (리뷰 B-11)

## 명세(spec.html)의 P2·P3 항목 (리뷰 C-1)
- SSE 실시간 실행 스트림(Last-Event-ID로 이어받기). MVP는 1초 폴링
- 노드 복사·붙여넣기(ID 재발급)
- 미니맵·맞춤 보기 (React Flow 기본 컴포넌트로 비용 낮음)
- 워크플로우 버전 목록·복원 (위의 "워크플로우 버전 관리"와 함께)
- `/metrics`(큐 대기, 실행 시간)와 부하·지연 측정 문서
- 키보드 접근성(노드 이동·연결을 키보드로)
- Delay 노드, Webhook Out 노드
- 웹훅 트리거(`POST /hooks/:token`)
- 자동 정렬(dagre 등)
- 자연어로 흐름 초안 생성(스키마와 연결 검증을 통과한 결과만 반영)
