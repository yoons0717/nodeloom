# 백로그

지금은 하지 않기로 한 아이디어. 한 줄씩.

- 다중 사용자 확장: 가입, 사용자별 소유권 검사(인가), 사용자 격리
- 시크릿 저장소(화면 입력 + DB 암호화 저장, 사용자별): 다중 사용자 확장과 함께 진행. `$secrets.NAME` 참조 문법은 그대로 두고 값을 가져오는 곳만 교체
- 자동 저장 + 게시(n8n 2.x, Zapier 방식): 편집은 초안으로 몇 초마다 자동 저장하고, 스케줄·실행은 "게시된 흐름"으로만. 워크플로우에 게시본 칸, 게시 버튼, 아래 버전 관리와 함께. MVP는 직접 저장 + 상태 칩 (M6 6-h)
- 워크플로우 버전 관리: 불변 버전 테이블, 버전 목록·복원 화면, 낙관적 락(409). MVP는 실행 시점 그래프 스냅샷만 저장
- 코드 노드(JavaScript): 실사용 흐름에서 표현식으로 안 되는 경우가 실제로 생기면 재검토. 격리 실행 방식이 선결 과제
- 표현식 쉬운 층 UI: 앞 노드 출력에서 클릭해 경로 넣기, Condition 폼(값 / 연산자 / 값 → 내부적으로 JSONata로 변환)
- 노드 참조 키를 바꿀 때 그 키를 쓰는 표현식을 자동으로 고쳐 주기. MVP는 "없는 키 참조" 검증 오류만 표시
- 워크플로우(Trigger)별 시간대 지정: 다중 사용자 확장과 함께. MVP는 `APP_TIMEZONE` 하나
- 성능 회귀 감시: CI에서 번들 크기, Lighthouse 기준 초과 시 실패 처리
- 브라우저 번들의 zod 줄이기: 모든 화면이 zod의 언어별 오류 문구(압축 약 40KB)를 함께 받는다. 브라우저 코드는 타입만 쓰고 검사는 서버에서 하거나, zod/mini로 바꾼다. M9에서는 그대로 둠
- 줌 배율별 노드 단순화(저배율에서 제목만 표시)
- 표현식 미리보기 입력 지연 개선(디바운스, Web Worker, INP 측정)
- 실행 기록 목록 성능: DB 인덱스 + 커서 페이지네이션 + 목록 가상화
- 상태 저장 노드("지난번 값" 읽기·쓰기): 실사용 흐름이 "변화 감지" 형태로 정해지면 재검토
- 데모 서버 자동 초기화(1시간마다 pg-boss cron으로 시드 재적용 + 안내 배너)
- 데모 예제 워크플로우 잠금 + 복제해서 편집
- 합류 노드 방식 선택(모두 기다림 / 하나라도), n8n Merge 노드 방식. MVP는 "하나라도 성공하면 실행" 고정
- 노드별 오류 출력 포트(실패 시 같은 흐름 안에서 분기). MVP는 "실패 시 다른 워크플로우 실행"
- API와 실행 워커 프로세스 분리(같은 코드, 진입점 2개). MVP는 한 프로세스
- 노드 하나만 테스트 실행("이 노드까지 실행"). MVP 2차는 마지막 실행 데이터로 미리보기
- HTTP 요청 멱등 키 헤더 지원(재개 시 중복 요청 완화). MVP는 "최소 한 번 실행" 한계 명시
- 휴대폰 편집과 터치 캔버스 제스처(두 손가락 이동·확대, 길게 눌러 연결). 지금은 768px 이상에서만 편집하고 좁은 화면은 안내 + 읽기 전용

## 처음 기능 명세에서 미룬 항목
- SSE 실시간 실행 스트림(Last-Event-ID로 이어받기). MVP는 1초 폴링
- 노드 복사·붙여넣기(ID 재발급)
- 미니맵 (React Flow 기본 컴포넌트로 비용 낮음. 맞춤 보기는 이미 있음)
- `/metrics`(큐 대기, 실행 시간)와 부하·지연 측정 문서
- 키보드 접근성(노드 이동·연결을 키보드로)
- Delay 노드, Webhook Out 노드
- 웹훅 트리거(`POST /hooks/:token`)
- 자동 정렬(dagre 등)
- 자연어로 흐름 초안 생성(스키마와 연결 검증을 통과한 결과만 반영)
- 밝은 테마: `docs/DESIGN.md`의 색 토큰을 밝은 값으로 한 벌 더 정의하고 시스템 설정을 따름

## 정리할 것
- 코드 주석의 결정 번호(`DECISIONS 7-2` 등): `docs/DECISIONS.md`는 저장소에 없어 다른 사람이 따라갈 수 없다. 공개 배포 전에 번호를 빼거나 이유를 문장으로 바꾼다. CONVENTIONS 4장 "결정 근거" 규칙도 함께 바꾼다
