# Nodeloom 프로젝트 계획

> 결정의 근거와 검토한 대안은 `docs/DECISIONS.md`, 미룬 아이디어는 `docs/BACKLOG.md`에 있다. 이 문서는 "지금 무엇을 만드는가"의 요약이다.

## 1. 목표

**노드 기반 워크플로우 자동화 도구**(Node-based workflow automation). 노드를 이어 붙여 반복 작업 흐름을 만들고, 서버가 대신 실행해 준다. 1인용.

> README 한 줄 소개: "Nodeloom — 노드를 이어 반복 작업을 자동화하는 워크플로우 도구 (Node-based workflow automation)"

- **1순위: 풀스택 포트폴리오.** 인터랙티브 에디터, 측정 가능한 렌더링 최적화, 모노레포, 가벼운 NestJS 백엔드와 실행 엔진을 보여준다.
- **2순위: 실제 사용.** MVP 완료 시점에 실사용 흐름 1개가 매일 스케줄로 돌아간다.
- 공개 데모는 채용 담당자가 에디터를 직접 만져 보는 제한 모드(mock 실행만)다. 실제 외부 호출은 개인 서버에서만 한다.

## 2. MVP 범위

MVP는 두 단계로 나눈다. 각 단계에는 막혔을 때 먼저 공개할 **최소선**과 목표인 **완성선**을 둔다.

### 1차: 에디터와 공개 데모
| 구분 | 내용 |
|---|---|
| 최소선 | 에디터(노드 4종 추가·이동·연결·삭제, 연결 검증과 거부 사유, Undo/Redo, 설정 패널과 JSONata 문법 검사), 저장·불러오기, 관리자 로그인, 데모 모드, 공개 배포, 성능 기준선(20/200/1000) 측정 |
| 완성선 | 최소선 + 성능 개선 전후 수치(① 노드 리렌더와 프레임 시간 ② 라우트별 번들, LCP·INP)를 README 표로 정리 |

### 2차: 실행 엔진과 실사용
| 구분 | 내용 |
|---|---|
| 최소선 | 실행 엔진(노드 4종 실행, 분기·합류, 재시도·시간 제한, SSRF 방어, 마스킹), 수동 실행, 실행 기록·상세 화면(폴링), 스케줄, 실패 알림 워크플로우, **실사용 흐름을 개인 서버에 스케줄로 등록해 매일 실행 시작** |
| 완성선 | 최소선 + 실사용 흐름 7일 연속 성공(MVP 완료 기준), 큰 JSON 보기 성능 수치(③), 마지막 실행 데이터로 표현식 미리보기 |

### MVP 밖 (요약, 전체 목록은 BACKLOG)
다중 사용자와 화면 시크릿 관리, 버전 목록·복원, 코드 노드, 상태 저장 노드, 노드별 오류 포트, SSE, 미니맵, 복사·붙여넣기, 웹훅 트리거, 모바일 편집, 데모 자동 초기화.

## 3. 핵심 동작 규칙

| 영역 | 규칙 |
|---|---|
| 노드 | Trigger(정확히 1개, 수동과 cron 스케줄), HTTP, Transform, Condition(참·거짓 포트) |
| 값 참조 | JSONata 2.2 이상. 루트는 직전 노드 출력. 부모가 여럿이면 `{ 참조키: 출력 }`. 다른 노드는 `$nodes.<참조키>`, 비밀값은 `$secrets.NAME`. 문자열 칸은 `{{ }}`, HTTP 본문은 JSONata 식 |
| 실행 | 실행 1개 = job 1개. 위상 정렬 순서로 실행하고 병렬 갈래는 동시에. 재시작하면 성공한 노드는 건너뛰고 이어서 실행. 항상 Run의 스냅샷만 읽는다 |
| 분기·합류 | 선택되지 않은 포트 쪽은 SKIPPED. 부모가 여럿이면 하나라도 성공했을 때 실행. Condition 결과가 불리언이 아니면 FAILED |
| 실패 | HTTP는 연결 실패, 타임아웃, 5xx, 408, 429만 지수 백오프로 재시도. 최종 실패하면 하위 노드는 SKIPPED, Run은 FAILED, 지정한 실패 알림 워크플로우를 실행 |
| 시간 제한 | HTTP 1~30초(기본 10초), JSONata 1초, 실행 전체 5분(`RUN_TIMEOUT`) |
| 동시 실행 | 워크플로우당 1개(부분 유니크 인덱스). 실패 알림 실행은 예외 |
| 검증 | 저장은 자유(초안). 실행은 서버가 core로 다시 검증. 스케줄 실행에서 검증에 실패하면 Run FAILED |
| 보존 | 끝난 실행 기록은 30일 보존(`RUN_RETENTION_DAYS`). 데모에서는 정리 작업도 돌지 않는다 |

## 4. 기술 스택

| 영역 | 선택 | 이유 (한 줄) |
|---|---|---|
| 모노레포 | pnpm workspace + Turborepo | 프론트와 서버가 같은 검증 코드를 공유 |
| 프론트 | Next.js 16 App Router | 공고 키워드 + 서버 컴포넌트(읽기 화면)와 클라이언트(에디터) 경계 경험 |
| 캔버스 | React Flow 12(제어 모드) | 에디터를 빨리 완성하고 실무형 성능 개선에 집중 |
| 상태 | Zustand v5(에디터, 인스턴스별 스토어) + TanStack Query(서버 상태) | 노드 단위 구독, 검증된 조합 |
| 스타일 | Tailwind v4 + shadcn/ui | 서버 컴포넌트 호환, 접근성 부품 |
| 폼·검증 | 폼 라이브러리 없음 + zod 4 | 설정 패널의 원본을 스토어 하나로 유지(Undo 일관성) |
| 백엔드 | NestJS 12(ESM, API, 워커, 스케줄러 한 프로세스) | 가볍게, 실행 엔진은 `ExecutorModule`로 분리 |
| 모듈·린트 | 전부 ESM, 루트 ESLint flat config 하나 | 도구 기본값과 같은 방향, 비동기 버그를 잡는 타입 정보 규칙 |
| DB·ORM | PostgreSQL + Prisma 7 | JSONB, 단순한 마이그레이션 |
| 큐 | pg-boss | Redis 없음, Run 생성과 job 등록을 한 트랜잭션으로 |
| 인증 | 관리자 1명, bcrypt 해시(환경 변수), JWT 7일, httpOnly·Secure·Lax 쿠키 | 1인 도구에 맞춘 최소 구성 |
| 테스트 | Vitest(전체) + Testcontainers(통합) + Playwright(e2e, 벤치) | 러너 통일, 실제 DB로 엔진 규칙 검증 |
| 운영 | pino(`runId`), `/health`, Swagger, GitHub Actions | 기본기 |

## 5. 구조

```
nodeloom/
├─ apps/
│  ├─ web/      Next.js: 목록·실행 기록(서버 컴포넌트), 에디터(클라이언트), 커맨드 스택
│  ├─ api/      NestJS: auth, workflows, runs, executor(pg-boss), mock, SSRF, 마스킹
│  └─ e2e/      Playwright: e2e 시나리오 + 성능 벤치
├─ packages/
│  └─ core/     그래프 타입, 노드 zod 스키마, 검증, 위상 정렬, 템플릿 (순수 TS, tsc로 ESM 출력)
├─ docs/        spec.html, DECISIONS.md(ADR), BACKLOG.md, PROJECT_PLAN.md, milestones/(마일스톤별 상세 계획)
├─ docker-compose.yml   postgres (+ 운영 시 web, api)
└─ .github/workflows/ci.yml
```

- 브라우저는 Next의 `/api/*`만 호출하고, Next rewrites가 NestJS로 중계한다(같은 출처, NestJS 비공개).
- 데이터: `workflows`(그래프 JSON, 실패 알림 대상), `runs`(스냅샷, 상태, 실행 종류: manual / schedule / failure), `node_runs`(입력·출력, 시도 번호).
- 스케줄은 별도 컬럼이 아니라 그래프의 Trigger 설정(cron)에서 읽어, 저장과 같은 트랜잭션으로 pg-boss에 등록·해제한다.

## 6. 마일스톤과 완료 기준

기간은 정하지 않는다. 마일스톤마다 "계획 제시 → 승인 → 구현 → 완료 기준 확인 결과 보고 → 멈춤" 순서로 진행한다. **(완성선)** 표시가 붙은 항목은 막히면 뒤로 미룰 수 있다. 마일스톤별 상세 계획은 `docs/milestones/M<n>.md`에 둔다.

- 1차 최소선 = M0~M3 + M4의 데모 배포 / 1차 완성선 = + M4의 성능 개선
- 2차 최소선 = M5 + M6(완성선 항목 제외) + M7의 실사용 시작 / 2차 완성선 = 나머지

| 마일스톤 | 내용 | 완료 기준 |
|---|---|---|
| **M0 기반** | 모노레포, web·api 뼈대, Postgres(Compose), Prisma, Vitest(Nest 12 템플릿 기본, 필요하면 SWC), Testcontainers, CI 4종. 8절 확인 목록 중 M0 항목 수행 | `pnpm install` → `docker compose up -d` → `pnpm dev`로 둘 다 뜬다. 브라우저에서 Next를 거쳐 `/api/health`가 DB 정상을 반환한다. CI가 통과한다. 확인 결과가 DECISIONS.md에 기록된다 |
| **M1 core** | 그래프 타입, 노드 스키마(`schemaVersion`), 검증(순환, 중복, 자기 연결, Trigger 1개, 닿지 않는 노드, 없는 참조 키), 위상 정렬, 합류 판정, 템플릿 해석 | 각 규칙의 성공·실패 케이스 단위 테스트 통과 |
| **M2 에디터** | (저장 없이 메모리에서 동작) 시작 전 React Flow 12와 React 19 호환 확인. React Flow 제어 모드, 팔레트, 연결 검증과 거부 사유, 삭제, 커맨드 스택(합치기 포함), 설정 패널(zod 오류 배지, JSONata 문법 검사), 성능 HUD, 벤치 모드 | e2e "노드 추가 → 연결 → 순환 연결 거부 → Undo" 통과. 벤치 기준선 표(20/200/1000) 기록 |
| **M3 저장·인증·데모** | 워크플로우 CRUD, 관리자 로그인(bcrypt, JWT 쿠키, 속도 제한, helmet), `pnpm admin:hash`, 목록 화면(서버 컴포넌트), 에디터 저장·불러오기, `DEMO_MODE`(Guard, 상한, 관리자 로그인 끔), 모바일 안내 | 저장 후 새로고침해도 복원. 로그인 없으면 접근 차단(데모 제외). 데모 모드 규칙 통합 테스트 통과 |
| **M4 배포·성능 개선·1차 마감** | ① 11-1 결정 후 데모 배포(먼저) ② (완성선) ①② 성능 개선 ③ README(아키텍처, 성능 표) | 공개 URL 동작(최소선). README에 ①② 전후 표, 시도했으나 효과 없던 방법도 DECISIONS.md에 기록(완성선). **1차 완료 선언** |
| **M5 실행 엔진** | 시작 전 pg-boss의 Prisma 트랜잭션 사용과 JSONata 가드레일 동작 확인. pg-boss, 실행 job(재개 포함), 노드 4종 실행기, JSONata 가드레일, 재시도·시간 제한, SSRF(사설 허용 목록, mock 예외), 마스킹, 실행 전 검증, 동시 실행 제한, 실패 알림(워크플로우 설정 UI 포함), mock 주소, 실행 버튼, 워크플로우 삭제 규칙(B-4), 노드 설정의 최악 소요 시간 표시 | 통합 테스트 통과: 분기 SKIPPED, 합류, Condition 비불리언 FAILED, 재시도 대상, 전체 시간 제한, 재개 시 성공 노드 건너뜀, 동시 실행 거부, 실패 알림 실행(연쇄 없음), 사설 IP 차단, 마스킹, 실행 중 삭제 거부 |
| **M6 스케줄·실행 화면** | cron 스케줄(`APP_TIMEZONE`, 저장과 같은 트랜잭션), 실행 기록·상세(서버 컴포넌트 + 상태 폴링, 노드 선택 시 입출력), (완성선) 큰 JSON 보기(③), (완성선) 마지막 실행 데이터 미리보기, 30일 정리 | 스케줄 시각에 실행되는 것을 통합 테스트로 확인. 데모에서 mock 실행 → 상세 화면 확인. (완성선) ③ 전후 수치 기록 |
| **M7 실사용·MVP 마감** | 실사용 흐름 확정(1-2), 개인 서버 배포(11-1), 운영 가이드 | 실사용 흐름 스케줄 등록과 첫 성공, 의도적 실패로 실패 알림 수신 확인(최소선). 7일 연속 성공(완성선). **7일 연속 성공 시 MVP 완료 선언** |

## 7. 주의할 점

| 항목 | 내용 |
|---|---|
| 최소 한 번 실행 | 요청을 보낸 직후 결과를 저장하기 전에 서버가 죽으면 재개할 때 같은 요청을 다시 보낸다. README에 한계로 명시 |
| 마스킹 한계 | 원래 값과 URL 인코딩 형태만 가린다. Base64 등 다른 인코딩은 입력 기록과 로그에 남을 수 있다 |
| SSRF 예외 | `MOCK_BASE_URL`과 `HTTP_ALLOW_PRIVATE`만 예외다. 메타데이터 주소는 어떤 경우에도 차단 |
| bcrypt 해시와 Compose | `.env`의 `$`는 `$$`로 적어야 한다. `pnpm admin:hash` 출력을 그대로 사용 |
| 시간대 | 서버와 브라우저 모두 `APP_TIMEZONE`으로 시각을 표시(hydration 불일치 방지) |
| 스토어 | Zustand 스토어는 에디터마다 생성. 모듈 전역 스토어 금지 |
| 데모 | 자동 초기화와 기록 정리가 없다. 지저분해지거나 DB가 커지면 시드를 다시 적용 |
| 시간 제한 | HTTP 재시도가 많은 노드가 여럿이면 전체 5분을 넘을 수 있다. 노드 설정에 최악 소요 시간 표시 |
| 범위 | 진행 중 떠오른 아이디어는 BACKLOG에만 추가하고, 현재 마일스톤이 끝나기 전에는 구현하지 않는다 |
