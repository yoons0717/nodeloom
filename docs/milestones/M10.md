# M10 실사용·MVP 마감

> **상태: 계획 승인 (2026-10-19), 구현 전.** 상위 문서: `docs/PROJECT_PLAN.md` 4절.

## 왜 하나

실행 엔진, 스케줄, 실패 알림은 M4·M5에서 만들었지만 아직 스케줄로 저절로 돈 적이 없다. 지금까지는 개발 서버에서 수동 실행으로만 확인했고, 개발 서버는 켜 둔 동안에만 돈다. MVP 완료 기준은 "실사용 흐름이 개인 서버에서 매일 스케줄로 돌고 7일 연속 성공"이다.

개인 서버는 아이맥(M1)으로 정했다. 늘 켜 두지 않고 매일 06:55에 깨워 30분 동안 깨어 있게 한다(`pmset repeat wakeorpoweron MTWRFSU 06:55:00`, 잠자기 30분). 2026-10-18·19 아침에 06:55 깨어남 → 07:25 잠듦을 로그로 확인했다.

## 목표

- 아이맥에서 운영용 Nodeloom이 개발 환경과 섞이지 않고 돈다. 잠자기 뒤에는 손대지 않아도, 재부팅 뒤에는 로그인만 하면 다시 돈다.
- 실사용 흐름이 07:00대에 스케줄로 실행되고, 실패하면 실패 알림이 온다.
- 같은 이름의 워크플로우를 만들거나 저장할 수 없다.
- 운영 방법(시작, 중지, 업데이트, 로그, 백업)이 문서에 있다.

## 실사용 흐름

개발 DB에서 만들어 수동 실행으로 확인한 것을 운영 DB로 옮긴다.

| 흐름 | 스케줄 | 하는 일 | 확인한 것 |
|---|---|---|---|
| 아침 브리핑 | 매일 07:00 | 서울 날씨·대기질, 환율을 동시에 받아 한 메시지로 디스코드에 보낸다 | 수동 실행 성공, 수신 |
| 수원 날씨 | 매일 07:05 | 수원 3시간 간격 온도를 보내고, 07~21시에 비가 오면 우산 줄을 붙인다 | 식과 검사만(엔진 실행 전) |
| 실패 알림 | 위 두 흐름이 실패할 때 | 실패한 흐름, 노드(제목과 참조 키), 사유를 디스코드 임베드로 보낸다 | 일부러 실패시켜 수신 |

7일 연속 성공은 아침 브리핑으로 센다(PROJECT_PLAN 1절 "실사용 흐름 1개").

## 단계

### 10-a. 워크플로우 이름 중복 금지
- DB에 이름 유니크 제약을 두고(대소문자 구분), 같은 이름으로 만들거나 저장하면 409와 이유를 돌려준다. 화면은 저장 실패와 같은 자리에 그 이유를 보인다.
- "새 워크플로우"를 만들 때 이름이 겹치면 서버가 "새 워크플로우 2", "새 워크플로우 3"처럼 번호를 붙인다.
- 마이그레이션은 제약만 더한다. 운영 DB는 새로 만들고, 개발 DB에는 겹친 이름이 없다(2026-10-19 확인). 겹친 이름이 있으면 마이그레이션이 실패하므로 그때 손으로 고친다.
- 테스트: 같은 이름으로 만들기·이름을 바꿔 저장하기가 409, 번호 붙이기.

### 10-b. 운영 실행 구성
- 같은 아이맥에서 개발과 운영을 나눈다. 운영은 별도 폴더(별도 clone), 별도 `.env`, 별도 Postgres(compose 프로젝트 이름과 포트를 다르게), 별도 포트(web·api)를 쓴다. 운영 DB를 개발 DB와 같이 쓰면 개발 서버의 pg-boss도 같은 스케줄을 실행한다.
- 운영은 프로덕션 빌드로 띄운다(`next start`, `node dist/main`). launchd로 로그인 시 자동 시작하고, 죽으면 다시 띄운다. Colima와 Postgres 컨테이너도 자동 시작한다.
- 정전 뒤 다시 켜지게 `pmset autorestart 1`을 켠다(지금 0).
- **재부팅 뒤 한계:** 이 아이맥은 FileVault가 켜져 있고 자동 로그인이 없다. 재부팅(정전, macOS 업데이트)하면 잠금 해제 화면에서 멈추고, 로그인하기 전까지 앱이 뜨지 않는다. 로그인은 사람이 한다(아래 "정한 것"). 계획된 업데이트는 `fdesetup authrestart`로 재시작해 잠금 해제를 한 번 건너뛴다.
- 확인: 재부팅 뒤 로그인만 하면 web·api가 응답한다. 잠들었다 깬 뒤에도 응답한다.

### 10-c. 잠자기와 스케줄 점검
- 깨어난 직후 스케줄이 제시각에 도는지 본다. 07:00 이전에 api, Postgres(Colima VM), 네트워크가 모두 다시 붙는지, VM 시계가 잠든 사이 밀리지 않는지 확인한다.
- 실행 기록 정리 작업을 03:00에서 07:15로 옮긴다(`run-cleanup.ts`). 03:00은 아이맥이 잠든 시각이라 지금은 돌지 않는다.
- 문제가 보이면 원인과 대응을 여기에 적는다. Postgres가 원인이면 macOS에 직접 설치하는 것으로 바꾼다.
- **결과 (2026-10-20):** 07:00 회차가 실행되지 않았다(07:05·07:15는 실행). Colima 가상 머신의 시계가 잠자기 동안 16분 뒤처졌다가 06:53에 한 번에 맞춰졌고(`lima-guestagent` 로그), pg-boss는 DB 시계와의 차이를 10분마다만 다시 재므로 그동안 회차 판단이 밀려 있다가 07:00을 건너뛰었다. 대응 두 가지:
  - 운영 Postgres를 Homebrew `postgresql@18`(macOS에 직접 설치, 포트 5433)로 옮겼다. 가상 머신이 없어 시계가 어긋나지 않는다. Docker 쪽 데이터는 멈춘 컨테이너의 볼륨에 남아 있다.
  - 스케줄에 pg-boss `missed: 'once'`를 넣었다. cron 확인이 멈췄다 돌아오면 놓친 회차 중 가장 최근 하나를 늦게라도 실행한다(재시작·업데이트 중 놓친 회차도 같다).

### 10-d. 실사용 흐름 등록과 첫 성공
- 운영 `.env`에 비밀값(디스코드 웹훅)을 넣고, 세 흐름을 운영 DB에 옮긴다. 실패 알림의 링크는 운영 web 주소(`http://localhost:<운영 포트>`)로 바꾼다.
- 다음 날 07:00·07:05 스케줄 실행이 성공하고 디스코드에 오는지 본다.
- 운영에서 아침 브리핑을 일부러 한 번 실패시켜 실패 알림이 오는지 본다. 끝나면 되돌린다.

### 10-e. 운영 가이드
- 운영 가이드(`docs/OPERATIONS.md`, 이 기기 전용이라 저장소에 올리지 않는다): 시작·중지, 업데이트 순서(받기 → 설치 → 마이그레이션 → 빌드 → 재시작), 로그 위치, 깨우기·잠자기 설정, DB 백업과 복원 명령, 자주 생길 문제(알림이 안 옴 → 확인 순서).
- 서버가 꺼져 있거나 아이맥이 깨지 않으면 실패 알림도 오지 않는다(2026-10-19 아침이 그랬다. 실행 기록 0건). 가이드에 "07:10까지 아침 브리핑이 없으면 확인할 것"으로 적는다. 바깥에서 감시하는 장치는 두지 않는다.
- 업데이트는 운영 폴더의 스크립트 하나로 한다.

### 10-f. 7일 연속 성공과 MVP 마감
- 아침 브리핑의 7일 실행 기록을 확인한다. 중간에 실패하면 원인을 적고 처음부터 다시 센다.
- README와 PROJECT_PLAN에 MVP 완료를 표시한다.
