# M6 디자인 정리 계획

> 상위 문서: `docs/PROJECT_PLAN.md` 6절 M6. **상태: 진행 중. 2026-10-11 승인.** 디자인 리뷰(진단 F1~F18과 개선안, 2026-10-11)를 바탕으로 한다.

## 무엇을 만드나

- 색 토큰을 기본값 → 의미 → 부품 세 단으로 나누고, 상태 색(성공·경고·오류·실행 중)과 노드 종류 색을 더한다. 청록은 선택·포커스·주요 버튼·실행 중에만 쓴다.
- 버튼·입력 칸·배지를 정리해 같은 부품을 쓰게 하고, 글자 크기와 간격을 단계·4px 격자로 맞춘다.
- 노드 카드에 종류 글리프와 색, 설정 요약, 실행 상태를 넣는다.
- 에디터 상단 바를 한 줄 세 구역으로 다시 놓고, 실행 상세와 실행 기록 목록의 상태 표시를 배지로 통일한다.
- 실행 상세 오른쪽 패널(실행 순서, 입력/출력 탭, 복사, JSON 보기)도 데모대로 만든다(6-e, ①). M5의 5-e에는 1MB JSON 성능 측정과 개선만 남는다.

## 단계

단계마다 보고하고 멈춘다. 단계마다 따로 커밋할 수 있다.

### 6-a. 토큰
- `globals.css`를 표면·테두리·글자·강조·상태·노드 종류·연결선 토큰으로 나누고 Tailwind `@theme`에 등록한다
- 기존 이름(`--primary`, `--input`, `--divider` 등)은 새 토큰의 별칭으로 남겨 부품이 깨지지 않게 한다
- `docs/DESIGN.md` 표를 새 토큰으로 바꾼다. 화면은 거의 그대로다

### 6-b. 부품
- Button: primary(화면당 하나)·outline(hover 때 밝아짐)·ghost·danger, 높이 28·36·44
- Input과 Field: 테두리 대비 3:1, 포커스·오류 모양 통일. HTTP 쿼리·헤더 칸도 Field로 감싼다
- Badge: `tone`(neutral·running·success·warning·danger)과 글리프(✓ ▲ ! ● –). 노드 오류 배지, 상단 문제 칩, 패널 오류 목록을 이것으로 바꾼다
- `dark:` 클래스와 투명도 색을 지우고, 글자 단계(20·16·14·13·12·11)와 4px 격자로 맞춘다

### 6-c. 노드 카드
- 136×84 고정(Condition 136×108)(⑦). 1줄: 종류 글리프 칩 + 종류 이름(영문 고정, ⑨) + 오른쪽 상태·오류, 2줄: 제목, 3줄: 설정 요약(HTTP `GET /weather`, Trigger 반복, Transform 식 앞부분). 참조 키는 설정 패널 머리로 옮긴다
- 상태: hover, 선택(2px 청록 + 바깥 빛), 오류(빨간 테두리, 3줄에 첫 오류), 실행 중, 성공(기본 테두리 + "✓ 걸린 시간", ④), 건너뜀(점선, 흐리게)
- 포트 12px + 24px 누를 영역, 선을 끄는 동안 연결할 수 있는 포트 강조, 참·거짓 라벨 11px
- 카드를 바꾼 뒤 같은 벤치로 기준선을 다시 재서 `docs/PERFORMANCE.md`에 남긴다(②)

### 6-d. 상단 바와 실행 화면
- 에디터 상단 바: 높이 56, 한 줄. 왼쪽 ← 목록·이름(⑩)·저장 상태·되돌리기/다시 하기, 오른쪽 문제 배지·실행 기록·설정·저장(outline)·실행(primary). "실패하면 실행"은 설정 팝오버로 옮긴다
- 실행 결과는 실행 버튼 아래 토스트로, 안에 "결과 보기". 성공은 저절로 닫히고 실패는 직접 닫을 때까지 남는다(⑥)
- 실행 상세: 에디터와 같은 56px 머리글(← · 워크플로우 이름 / 실행 시각(③) · 상태 배지 · 종류·걸린 시간 · 실행 기록, 에디터에서 열기). 지나간 연결선은 청록, 안 간 갈래는 점선. Condition 카드에 고른 쪽 표시
- 실행 기록 목록과 홈: 상태는 배지, 스케줄 문구는 보조 글자색, 데모 표시는 neutral 배지
- 좁은 화면에서 에디터 대신 나오는 안내에 "실행 기록" 링크(⑧)
- 바뀐 문구·자리에 맞춰 RTL·e2e를 고친다

### 6-e. 실행 상세 패널
- 실행 순서: 노드가 실행된 순서대로 상태 글리프·제목·걸린 시간(Condition은 고른 쪽). 전체 시간의 절반을 넘긴 노드에는 경고 막대. 줄을 누르면 그 노드를 고른다
- 입력/출력 탭과 복사 버튼, 패널 남은 높이를 다 쓰는 JSON 보기(12/20, 키·숫자·문자열 색 구분, 객체 접기)
- 아래 한 줄에 고른 값을 다른 노드에서 읽는 식(`$nodes.<키>.<경로>`)

### 6-f. 화면 다듬기 (2026-10-12 추가)
- 공통 부품: 상단 바 `PageHeader`(목록·실행 기록·실행 상세), 오류 표시 `InlineError`. 뒤로 가기는 글자가 있는 ghost 버튼 하나("← 에디터")
- 목록: 행 전체를 링크로, 열을 grid로 맞춤, 삭제는 hover·포커스 때만, 데모 배지는 "데모" + 툴팁
- 실행 기록: 고정 열 grid, 날짜별 묶음, 상태 거르기(`?status=`), 실행 중 경과 시간, 실패 행 강조, 빈 상태 버튼
- 실행 상세: 요약을 머리글 아래 한 줄로, 실패한 실행은 처음 실패한 노드를 고른 채 열림, 패널 384px, 실행 순서 접기, 모든 행에 비율 막대
- 노드 패널·토스트·로그인: 시도 세그먼트, 좁은 화면 44px 탭, 식 복사, 토스트 두 줄, 비밀번호 보기
- 데모와 다른 곳(뒤로 가기 글자 버튼, 모든 행 비율 막대, 패널 384px)은 이 지시를 따른다. 실행 기록 "더 보기"는 API가 50건만 돌려주므로 빼고 안내만 둔다

### 6-g. 공통 왼쪽 사이드바 (2026-10-12 추가)
- 라우트 그룹 `(app)`에 사이드바를 두고 목록·에디터·실행 기록·실행 상세가 함께 쓴다(로그인·벤치 제외). 화면별 뒤로 가기 버튼은 없앤다
- 사이드바: 워크플로우 찾기(⌘K), 전체 워크플로우·모든 실행(24시간 실패 수), 워크플로우 트리(상태 점, 편집·실행 기록·설정), 새 워크플로우, 계정·로그아웃. 펼침 240px·접힘 56px, 접힘 상태 저장, 에디터에서는 기본으로 접힘, 좁은 화면은 왼쪽 드로어
- 새 화면: 모든 실행 `/runs`, 워크플로우 설정 `/w/[id]/settings`(상단 바의 "설정" 팝오버를 옮김)
- API 추가: 목록에 마지막 실행과 실행 수, 모든 워크플로우의 실행 목록 `GET /runs`, 요약 `GET /runs/summary`(24시간 실패 수, 실행 중 수)

### 6-h. 에디터 상단 바 다듬기 (2026-10-12 추가)
- Claude Design 상단 바 시안의 1b + 2a. 저장 버튼을 없애고 저장 상태 칩이 곧 저장 버튼이 된다(바뀌었을 때만 칩 안에 "저장 ⌘S", 실패하면 "다시 시도"). 저장된 상태는 아무것도 보이지 않는다(시안의 "✓ 저장됨"은 평소에 떠 있는 성공 표시라 어색해서 뺌)
- 되돌리기·다시 하기는 상단 바에서 캔버스 도구 막대(확대·축소 앞)의 아이콘으로 옮기고, 툴팁에 되돌릴 동작 이름을 보여 준다
- 상단 바: 이름 · 저장 상태 칩 ……… 문제 배지 · 실행. 실행은 지금처럼 묻지 않고 먼저 저장한다
- 고르지 않은 것: 1a(실행 전 확인 창), 1c 자동 저장(쓰다 만 흐름이 스케줄로 실행됨, BACKLOG의 "자동 저장 + 게시"), 2b 동작 목록, 2c 삭제 직후 토스트(실행 토스트와 위치가 겹침, 삭제 실수가 잦으면 다시 본다)
