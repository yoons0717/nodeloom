# M6 디자인 정리

> **상태: 완료 (2026-10-15).** 상위 문서: `docs/PROJECT_PLAN.md` 4절. 디자인 리뷰(진단 F1~F18과 개선안, 2026-10-11)를 바탕으로 하고, 리뷰에 딸린 데모 화면을 아래에서 "디자인 시안"이라 부른다.

## 왜 하나

화면마다 색·크기·부품이 제각각이었다. 디자인 리뷰의 진단 F1~F18을 고치고 화면을 디자인 시안에 맞춘다. 지금 규칙은 `docs/DESIGN.md`에 있고, 여기에는 단계마다 한 일과 그때 정한 것만 남긴다.

완료 기준: 진단 F1~F18 해결, 색은 토큰으로만(`dark:` 클래스·`/10` 투명도 색·`text-[10px]` 같은 임의 크기 0건), 입력 칸·버튼 테두리 대비 3:1 이상, 노드 카드를 바꾼 뒤 성능 기준선 다시 재기, lint·타입 체크·테스트·빌드·e2e 통과(CI를 쓸 수 없어 로컬에서).

## 단계

### 6-a. 토큰
색 토큰을 표면·테두리·글자·강조·상태·노드 종류·연결선으로 나누고 Tailwind `@theme`에 등록했다. 기존 이름(`--primary`, `--input` 등)은 새 토큰의 별칭으로 남겨 부품이 깨지지 않게 했다.

### 6-b. 부품
Button·Input·Field·Badge를 정리해 같은 부품을 쓰게 하고, 글자 단계와 4px 격자로 맞췄다.

### 6-c. 노드 카드
136×84 고정 카드에 종류 글리프·제목·설정 요약 세 줄을 넣고, 상태(선택·오류·실행 중·성공·건너뜀)를 나눴다. 참조 키는 설정 패널 머리로 옮겼다. 바꾼 뒤 성능 기준선을 다시 쟀다(`docs/PERFORMANCE.md`).

### 6-d. 상단 바와 실행 화면
에디터 상단 바를 한 줄로 다시 놓고, 실행 결과는 실행 버튼 아래 토스트로 보여 준다. 실행 상세에서 지나간 연결선은 청록, 안 간 갈래는 점선이다.

### 6-e. 실행 상세 패널
실행 순서(전체 시간의 절반을 넘긴 노드는 경고 막대), 입력/출력 탭과 복사, JSON 보기, 고른 값을 다른 노드에서 읽는 식(`$nodes.<키>.<경로>`)을 넣었다.

### 6-f. 화면 다듬기 (2026-10-12 추가)
공통 부품 `PageHeader`·`InlineError`를 만들고, 실행 기록에 날짜별 묶음과 상태 거르기(`?status=`), 실행 상세에 처음 실패한 노드를 고른 채 열기를 넣었다. 디자인 시안과 다르게 한 곳(모든 행 비율 막대, 패널 384px)은 화면 다듬기 요청을 따랐다. 실행 기록 "더 보기"는 API가 50건만 돌려주므로 빼고 안내만 둔다.

### 6-g. 공통 왼쪽 사이드바 (2026-10-12 추가)
라우트 그룹 `(app)`에 사이드바를 두고 화면별 뒤로 가기 버튼을 없앴다. 새 화면 모든 실행(`/runs`)과 워크플로우 설정(`/w/[id]/settings`), API(목록의 마지막 실행, `GET /runs`, `GET /runs/summary`)를 더했다.

### 6-h. 에디터 상단 바 다듬기 (2026-10-12 추가)
디자인 시안 중 저장 방식 1b와 되돌리기 위치 2a를 골랐다. 저장 버튼을 없애고 저장 상태 칩이 곧 저장 버튼이 된다. 저장된 상태는 보이지 않는다(시안의 "✓ 저장됨"은 평소에 떠 있는 성공 표시라 어색해서 뺌). 되돌리기는 캔버스 도구 막대로 옮겼다. 고르지 않은 것: 1a(실행 전 확인 창), 1c 자동 저장(쓰다 만 흐름이 스케줄로 실행됨, BACKLOG의 "자동 저장 + 게시"), 2b 동작 목록, 2c 삭제 직후 토스트(실행 토스트와 위치가 겹침).

### 6-i. 도움말 팝오버 (2026-10-13 추가)
식을 쓰는 칸과 노드 목록 항목에 `(?)` 도움말을 달았다. 바깥을 눌러도 닫히지 않는다(식을 보면서 입력). 칸 아래 hint는 한 줄로 줄이고, "식이 올바릅니다"와 없는 노드를 가리키던 예시는 지웠다.

### 6-j. 반응형 디자인 (2026-10-13 추가)
고친 문제: 768~1279px에서 캔버스가 너무 좁음(768px에서 168px), 폭으로 터치 여부를 짐작함, 마우스를 올려야만 보이는 정보(`title=`), 좁은 화면에서도 에디터를 통째로 그림, 노드 추가가 끌어다 놓기뿐임. 규칙은 `docs/DESIGN.md` "반응형".

#### 반응형: 처음 계획과 달라진 점

| 처음 계획 | 구현 | 이유 |
|---|---|---|
| 사이드바: `resolveCollapsed`에 폭 조건을 더한다 | `resolveCollapsed`는 그대로 두고, 사이드바가 `rail`(접힘) · `responsive`(펼침: 레일과 펼친 모양을 둘 다 그리고 CSS로 하나만 보임) · `full`(드로어·겹쳐 열기) 세 가지로 그린다 | 폭을 JS로 재지 않아야 처음 그림이 서버와 같다. 저장값은 xl에서만 쓰인다 |
| 실행 상세: 위아래로 쌓을 때 패널은 캔버스 아래 | 아래 패널만 스크롤하고 캔버스는 화면에 남긴다. 노드를 고르면 패널의 `scrollTop`을 0으로 | 캔버스를 보면서 입출력을 볼 수 있게. 맨 위로 올리는 기준이 패널 하나라 단순하다 |
| 실행 상세: md – lg 패널 한 칸 | [오류 + 실행 순서 \| 노드 입출력] 두 칸 | 시안의 추가 제안을 따랐다. 쌓인 배치에서는 폭이 남는다 |
| 실행 기록: 거르기 칩 `전체 6`처럼 개수 | 개수 없음 | 칩을 서버 거르기(`?status=`)로 바꾸면서 "최근 50건 중 몇 건"을 셀 수 없어 뺐다 |
| hover 정보는 Tooltip, 터치는 누르면 팝오버 | `InfoTip` 하나(올리기·포커스로 열리고, 누르면 열고 닫는 툴팁) | 같은 내용을 두 부품으로 나누지 않는다 |
| 시안 레일 항목 32px | 터치에서 44px | 손가락 기준을 따랐다 |
| 시안 레일의 "모든 실행" 빨간 점 | 실패 수 숫자 배지 유지 | 상태는 Badge + 글리프로 보여 준다(DESIGN.md 원칙) |
| 저장 칩 글자 `xl:inline`으로 숨김 | `max-xl:sr-only` | 화면에서는 ●만 보이고 스크린 리더는 "저장 안 됨"을 읽는다 |
| (처음 계획에 없음) | 노드 카드 오류 배지의 읽는 이름은 "오류 n개"만. 겹친 설정 패널은 팝오버 안의 Esc로 닫히지 않는다 | 배지 이름에 오류 문구를 넣으면 같은 문구의 입력 칸 이름과 겹친다(문구는 카드 셋째 줄과 설정 패널에 있다). 도움말을 닫으려던 Esc가 패널까지 닫지 않게 |
| (처음 계획에 없음) "캔버스에 추가"가 놓는 자리 | 보이는 영역 가운데(md – lg는 겹쳐 열릴 설정 패널 320을 뺀 영역). 그 자리에 노드가 있으면 겹친다 | 새 노드가 선택된 채로 놓여 바로 끌어 옮길 수 있다. 빈 자리를 찾아 밀어 놓는 것은 하지 않기로 했다(2026-10-15) |
| 에디터: 겹쳐 나오는 설정 패널은 `--overlay` 배경 | `--surface` 배경(넓은 화면 패널과 같음) + 왼쪽 선 + 그림자 | `--overlay`(#28313D) 위 입력 칸 테두리(#5D6979) 대비가 2.36:1로 M6 기준(3:1)에 못 미친다. `--surface`에서는 3.13:1(2026-10-15) |

## 정한 것

| # | 질문 | 정한 것 | 검토한 대안 |
|---|---|---|---|
| ① | 범위 | 다섯 단계(6-e에서 바꿈: 처음에는 실행 상세 패널을 5-e로 미뤘으나, 화면을 디자인 시안과 맞추기로 하고 이번에 넣음) | 실행 상세 패널은 5-e와 함께 |
| ② | 성능 기준선 | 노드 카드를 바꾼 직후, 최적화 전에 다시 재 둔다. M2 기준선은 이전 카드로 잰 값이라 M9 성능 개선의 비교 기준이 될 수 없다 | 다시 재지 않음 |
| ③ | 실행을 부르는 이름 | 번호 대신 실행 시각("10월 11일 07:00"). 실행 기록 id에는 순번이 없고, 앞에서부터 세면 30일 정리 뒤에 번호가 바뀐다 | DB에 일련번호 칸 추가 |
| ④ | 노드 카드의 실행 결과 | 걸린 시간만. 상태 조회 응답에 노드별 시작·끝 시각을 더한다. "200 · 1.2 KB" 같은 결과 요약은 출력 내용이 필요해 상태 조회(입출력 없음)와 맞지 않아 뺀다 | 서버가 짧은 요약 글자를 만들어 상태 조회에 넣음 |

| ⑥ | 실행 결과 토스트 | 성공은 저절로 닫히고 실패는 직접 닫을 때까지 남는다. 저절로 닫히면 실패를 놓친다 | 모두 저절로 닫힘 |
