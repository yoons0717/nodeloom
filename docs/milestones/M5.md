# M5 스케줄·실행 화면 계획

> 상위 문서: `docs/PROJECT_PLAN.md` 6절 M5. **상태: 진행 중. 2026-10-11 승인.**

## 무엇을 만드나

- Trigger의 cron대로 **정해진 시각에 흐름이 저절로 실행**된다.
- 지난 실행을 **목록과 상세 화면**으로 본다. 상세에서는 노드별 상태가 보이고, 노드를 고르면 입력·출력이 보인다.
- 끝난 지 30일이 넘은 실행 기록은 매일 지운다.

## 완료 기준

| 완료 기준 | 확인 방법 |
|---|---|
| cron을 적고 저장하면 그 시각에 실행되고, 지우고 저장하면 멈춘다 | 브라우저에서 1분 뒤 cron으로 |
| 진행 중인 실행이 상세 화면에서 1초마다 바뀌고, 노드를 고르면 입력·출력·오류가 보인다 | 데모에서 mock 실행 → 상세 |
| 단계별 테스트, e2e, lint·타입 체크·빌드, CI가 통과한다 | `pnpm turbo run lint typecheck test build`, `pnpm e2e`, GitHub Actions |
| (완성선) 큰 JSON 보기 개선 전후 수치 기록, 마지막 실행 데이터로 식 미리보기 | `docs/PERFORMANCE.md`, 브라우저 |

## 단계

단계마다 보고하고 멈춘다. 5-e, 5-f는 완성선이다.

### 5-a. 스케줄 등록
- 스케줄은 Trigger `cron`에서 읽는다. 새 테이블 없음. pg-boss 스케줄 하나 = 워크플로우 하나(키: 워크플로우 id)
- 저장할 때 같은 트랜잭션에서 등록, cron이 없거나 틀리면 해제(②). 삭제할 때도 해제
- 다른 검사 오류는 등록을 막지 않는다(실행할 때 FAILED)
- 시간대는 `APP_TIMEZONE`. api에서도 읽고 시작할 때 검사한다. 브라우저에는 `next.config`의 `env`로 넘긴다(빌드할 때 고정)
- Trigger 설정의 "반복": 반복 안 함 / 매일 / 평일 / 매주 ○요일 / 매시간 / 직접 입력(cron). 고르면 cron으로 바꿔 저장하고, 저장된 cron이 선택지에 맞지 않으면 직접 입력으로 보여 준다
- 그 아래에 다음 실행 시각 3개, 직접 입력에서 틀린 cron이면 오류 배지(①)
- 데모: 등록하지 않고 "데모에서는 스케줄이 실행되지 않습니다" 표시
- **테스트:** cron 검사(6자리 거부 포함), 다음 시각이 시간대를 따름, 저장·해제·삭제, 등록이 실패하면 저장도 되돌아감, 데모

### 5-b. 스케줄 실행과 정리 작업
- 시각이 되면: 검사 실패 → Run을 바로 FAILED로 남기고 실패 알림 / 이미 실행 중 → 이번 회차 건너뜀 / 통과 → 실행(입력 `{}`)
- 서버가 꺼져 있던 동안의 회차는 건너뛴다(pg-boss 기본값). README 한계에 적는다(M6)
- 워커가 없던 동안(5-a만 있던 때) 큐에 쌓인 오래된 회차는 실행하지 않고 건너뛴다. 워크플로우가 지워졌으면 조용히 끝낸다
- 매일 03:00 끝난 실행 중 `RUN_RETENTION_DAYS`(기본 30)보다 오래된 것을 지운다. 데모에서는 돌지 않는다
- 멈춘 실행 처리(⑤)
- **테스트:** 위 세 갈래, 정리(진행 중·최근 기록은 남김), ⑤ 뒤 다음 실행이 막히지 않음, 데모. 시각 실행은 pg-boss 시험용 시계로 해 보고, 안 되면 실제로 1분 기다린다

### 5-c. 실행 기록 목록
- `/w/[id]/runs`: 상태, 종류(직접·스케줄·실패 알림), 시작 시각, 걸린 시간, 오류 한 줄(③)
- 에디터 상단 바에 "실행 기록" 링크, 실행을 시작하면 바로 "결과 보기"
- API: `GET /workflows/:id/runs`, `GET /runs/:id`, `GET /runs/:id/nodes/:nodeId`(입출력은 여기서만)
- **테스트:** API 통합(404, 목록에 입출력 없음, 노드 입출력이 시도별로)

### 5-d. 실행 상세와 e2e
- `/w/[id]/runs/[runId]`: 실행 당시 그래프를 읽기 전용 캔버스(④)에 그리고 노드별 상태 색
- 끝나지 않았으면 1초마다 상태만 조회. 노드를 고르면 패널에 시도별 입력·출력·오류
- 좁은 화면에서도 보인다(패널은 캔버스 아래)
- **테스트:** RTL 1개(노드를 고르면 패널), e2e "데모에서 실행 → 노드 상태 표시"

### 5-e. (완성선) 큰 JSON 보기
- 1MB 출력의 렌더 시간과 DOM 수를 재고, 개선한 뒤 다시 잰다. 개선 방법은 측정을 보고 정한다

### 5-f. (완성선) 마지막 실행 데이터 미리보기
- 마지막 실행 기록으로 식 결과를 설정 패널에 보여 준다. `$secrets`는 계산하지 않는다
