# M5 스케줄·실행 화면

> **상태: 완료 (최소선 2026-10-11).** 상위 문서: `docs/PROJECT_PLAN.md` 4절. 완성선 5-e, 5-f는 README와 실사용 시작을 먼저 하기로 하고 미뤘다.

## 왜 하나

- Trigger의 cron대로 정해진 시각에 흐름이 저절로 실행된다.
- 지난 실행을 목록과 상세 화면으로 본다. 상세에서는 노드별 상태가 보이고, 노드를 고르면 입력·출력이 보인다.
- 끝난 지 30일이 넘은 실행 기록은 매일 지운다.

## 만들면서 정한 것

- **스케줄 등록:** 스케줄은 Trigger `cron`에서 읽는다(새 테이블 없음, pg-boss 스케줄 하나 = 워크플로우 하나). 저장하는 트랜잭션에서 등록하고, cron이 없거나 틀리면 해제한다. 등록이 실패하면 저장도 되돌린다. 다른 검사 오류는 등록을 막지 않는다(실행할 때 FAILED).
- **시간대:** `APP_TIMEZONE` 하나. api는 시작할 때 검사하고, 브라우저에는 `next.config`의 `env`로 넘긴다(빌드할 때 고정).
- **반복 선택:** 반복 안 함 / 매일 / 평일 / 매주 ○요일 / 매시간 / 직접 입력(cron). 고르면 cron으로 바꿔 저장하고, 저장된 cron이 선택지에 맞지 않으면 직접 입력으로 보여 준다.
- **스케줄 실행:** 검사 실패면 Run을 바로 FAILED로 남기고 실패 알림, 이미 실행 중이면 이번 회차 건너뜀. 서버가 꺼져 있던 동안의 회차와 만들어진 지 2분이 넘은 회차는 실행하지 않는다(쌓인 회차가 한꺼번에 돌지 않게).
- **정리:** 매일 03:00에 `RUN_RETENTION_DAYS`(기본 30)보다 오래된 끝난 실행을 지운다.
- **데모:** 스케줄을 등록하지 않고 "데모에서는 스케줄이 실행되지 않습니다"를 보여 준다. 정리 작업도 돌지 않는다.
- **입출력 조회:** 노드 입출력은 `GET /runs/:id/nodes/:nodeId`에서만 준다. 목록과 상태 조회에는 넣지 않는다.

### 5-e. (완성선) 큰 JSON 보기
1MB 출력의 렌더 시간과 DOM 수를 재고 개선하는 작업. M9 9-c에서 쟀고, 드문 경우라 고치지 않았다(BACKLOG).

### 5-f. (완성선) 마지막 실행 데이터 미리보기
마지막 실행 기록으로 식 결과를 설정 패널에 보여 주는 기능. 만들지 않고 MVP 밖으로 빼서 BACKLOG에 옮겼다(2026-10-18).
