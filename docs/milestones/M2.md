# M2 에디터 계획

> 상위 문서: `docs/PROJECT_PLAN.md` 6절 M2. **상태: 완료 (2026-10-07).** 작은 결정 ①②③⑤⑥⑦은 기본값으로 확정(④는 M3로 이동).

## 무엇을 만드나

브라우저에서 노드를 놓고, 잇고, 설정하고, 되돌릴 수 있는 **에디터 화면**을 만든다. 이번 단계에서는 **저장하지 않고 브라우저 메모리에서만** 동작한다(저장은 M3). M1의 `@nodeloom/core` 규칙을 화면에 연결하는 단계다.

| 항목 | 내용 |
|---|---|
| 위치 | `apps/web/`(화면), `apps/browser-tests/`(새로 만듦: 이번에는 성능 벤치만. e2e 테스트는 M3 끝에 추가) |
| 쓰는 것 | React Flow 12(캔버스, 5-1), Zustand 5(에디터 상태, 4-2), shadcn/ui(기본 UI 부품, 4-3), `@nodeloom/core`(검증, 연결 판정, 참조 키) |
| 쓰지 않는 것 | NestJS, DB, TanStack Query(서버와 통신하지 않음) |

## 완료 기준

| 완료 기준 | 확인 방법 |
|---|---|
| 커맨드 스택(Undo/Redo, 합치기) 단위 테스트가 통과한다 | `pnpm --filter @nodeloom/web test` |
| 성능 기준선 표(노드 20 / 200 / 1000)가 기록된다 | `docs/PERFORMANCE.md` |
| 전체 lint, 타입 체크, 테스트, 빌드와 CI가 통과한다 | `pnpm turbo run lint typecheck test build`, GitHub Actions |

## 화면 구성

```
┌──────────────────────────────────────────────────────────────┐
│ 상단: 제목 · Undo · Redo · (저장·실행 버튼은 M3·M5에서)        │
├──────────┬──────────────────────────────────┬────────────────┤
│ 팔레트    │ 캔버스 (React Flow)               │ 설정 패널       │
│ 노드 4종  │ 노드, 연결선, 줌·팬, 다중 선택     │ 선택한 노드의   │
│ 검색      │ 연결 거부 사유 표시               │ 제목, 참조 키,  │
│ 끌어 놓기 │ 성능 HUD(벤치 모드)               │ 설정, 오류      │
└──────────┴──────────────────────────────────┴────────────────┘
```

- 경로: `/editor`(저장 전이라 id 없이 연다. M3에서 `/w/:id`로 바뀐다). 에디터 본체는 클라이언트 컴포넌트다(4-1)
- 처음 열면 Trigger 노드 1개가 놓인 빈 그래프로 시작한다(작은 결정 ⑦)
- 좁은 화면 안내(B-11)는 M3에서 목록 화면과 함께 넣는다

## 단계

M2는 크기가 커서 네 단계로 나누고, 단계마다 보고하고 멈춘다.

### 2-a. 에디터 상태와 커맨드 (화면 없음)
- **파일:** `apps/web/src/features/editor/store.ts`, `commands.ts`, 각 `*.test.ts`
- **내용:**
  - Zustand 스토어를 **에디터마다 새로 만든다**(`createStore` + React Context, B-12). 원본 그래프는 이 스토어 하나에만 둔다(5-1 제어 모드, 4-4)
  - 노드 단위 셀렉터 구독 같은 리렌더 최적화는 **하지 않는다.** M2는 최적화 전 기준선을 재는 단계이고, 개선은 M4에서 한다(4-2, 5-3)
  - 커맨드: 노드 추가, 노드 이동, 연결, 연결 삭제, 노드 삭제(붙은 연결 함께), 설정 변경, 제목·참조 키 변경
  - 커맨드마다 되돌리기(역연산)를 함께 정의하고 Undo/Redo 스택에 쌓는다. Undo한 뒤 새 커맨드를 실행하면 Redo 기록은 지운다
  - 연속 동작 합치기(4-4)
    - 드래그: 드래그하는 동안에는 위치만 갱신하고 기록하지 않는다. 드래그를 놓을 때 시작 위치와 끝 위치를 담은 이동 커맨드 하나를 기록한다
    - 타이핑: 같은 칸을 500ms 안에 이어서 입력하면 커맨드 하나로 합친다
  - 연결 커맨드는 core의 `canConnect`를 통과해야만 실행
- **web 테스트 환경:** Vitest를 web에 처음 설정한다(10-1). 이 단계의 테스트는 화면 없이 스토어와 커맨드만 검사

### 2-b. 캔버스와 팔레트
- **파일:** `apps/web/src/app/editor/page.tsx`, `apps/web/src/features/editor/canvas.tsx`, `palette.tsx`, `nodes/*.tsx`
- **내용:**
  - React Flow를 **제어 모드**로 연결: 스토어의 그래프를 React Flow 형식으로 바꿔 넘기고, React Flow의 변경 이벤트는 커맨드로 바꿔 스토어에 반영(5-1)
  - 노드 컴포넌트 4종: 제목, 참조 키, 오류 배지, 포트. Condition은 출력 포트가 참·거짓 두 개
  - 팔레트: 노드 4종 목록, 검색, 캔버스로 끌어 놓으면 놓은 위치에 추가. 참조 키는 core의 `nextNodeKey`로 자동 생성
  - 연결 검증: React Flow의 `isValidConnection`에 core `canConnect`를 연결. 연결 중에는 포인터 옆에 거부 사유 표시(순환, 중복, 자기 연결, 방향)
  - 단축키: Undo(Ctrl/Cmd+Z), Redo(Ctrl/Cmd+Shift+Z), 삭제(Delete, Backspace)
  - 줌·팬, 다중 선택(Shift, 박스), 그리드 스냅, 처음 열 때 전체가 보이게 맞춤은 React Flow 기능을 쓴다
  - 오류 배지: core `validateGraph` 결과를 노드에 표시. 참조 키를 바꾸면 그 키를 쓰던 식은 "없는 참조 키" 오류로 표시된다(자동 수정은 BACKLOG, 3-4)
- **첫 작업:** React Flow 12와 React 19(Next 16) 조합이 실제로 동작하는지 확인(확인 목록)

### 2-c. 설정 패널
- **파일:** `apps/web/src/features/editor/settings-panel.tsx`, `settings/*.tsx`
- **내용:**
  - 선택한 노드의 제목, 참조 키, 노드 종류별 설정 칸. 폼 라이브러리 없이 스토어를 직접 읽고 쓴다(4-4)
  - 노드 종류별 설정 화면은 **종류마다 직접 만든다**(작은 결정 ②)
  - 값 검증은 core의 노드 스키마(zod)로, JSONata 칸은 core의 문법 검사로 즉시 표시(A-5 1차 범위)
  - shadcn/ui 부품을 이 단계에서 필요한 것만 추가(Input, Textarea, Select, Switch, ScrollArea, Tooltip, Button, Badge). Tabs는 설정 칸이 한 화면에 들어가서 넣지 않았다
  - 디자인 토큰(`docs/DESIGN.md`)을 적용하고, 기존 에디터(상단 바, 팔레트, 노드 카드)도 토큰으로 바꾼다. 노드 오류 배지의 브라우저 기본 툴팁(`title`)은 shadcn Tooltip으로 바꾼다
  - 설정 오류 문구를 칸별 한국어로 보여 준다(지금은 zod 기본 영어 문구가 섞여 나옴)
  - 컴포넌트 테스트(RTL) 1개: 잘못된 값을 넣으면 설정 패널에 오류가 표시된다(10-2)

### 2-d. 성능 HUD와 벤치
- **파일:** `apps/web/src/features/editor/perf-hud.tsx`, `apps/web/src/app/bench/page.tsx`, `apps/browser-tests/`(새 패키지 `@nodeloom/browser-tests`)
- **내용:**
  - 성능 HUD: 노드 수, 실제로 그려진 노드 수, FPS
  - 벤치 모드: `/bench?nodes=N`이 N개 노드의 예시 그래프를 만들어 열고, React Profiler와 프레임 시간을 페이지 안에 모은다(5-3). 벤치 페이지는 개발 환경과 벤치 실행에서만 열린다(작은 결정 ③)
  - 벤치는 **프로덕션 빌드**(`next build` 후 `next start`)에서 잰다. 개발 모드는 React가 검사용으로 렌더를 두 번 하는 등 수치가 부풀기 때문이다
  - Playwright 벤치: 노드 20 / 200 / 1000에서 같은 드래그와 선택 변경을 반복하고, 리렌더 수와 프레임 시간을 표로 출력. 결과를 `docs/PERFORMANCE.md`에 **최적화 전 기준선**으로 기록(최적화는 M4)
  - 벤치는 CI에서 돌리지 않는다(5-3)
  - e2e 테스트는 쓰지 않는다. 화면 흐름(경로 `/w/:id`, 저장)이 자리 잡는 M3 끝에서 쓴다(H-1)

## 위험과 대응

| 위험 | 대응 |
|---|---|
| React Flow 제어 모드에서 드래그할 때마다 스토어가 바뀌어 리렌더가 많음 | M2에서는 그대로 두고 기준선으로 측정한다. 개선은 M4의 주제(5-3 ①) |
| React Flow 내부 상태와 스토어가 어긋남 | 원본은 스토어 하나. React Flow는 스토어에서 만든 값만 받는다 |
| 연결 거부 사유를 포인터 옆에 띄우는 방법이 React Flow 기본 기능에 없음 | 연결 중 상태 훅으로 현재 대상 포트를 읽어 직접 표시. 2-b 첫 작업에서 확인 |
| Undo 합치기 경계가 애매함(드래그 중 이동, 연속 타이핑) | 합치기 규칙을 2-a 단위 테스트로 먼저 고정 |
| 설정 칸에서 글자를 지우려고 Backspace나 Ctrl+Z를 눌렀는데 노드가 지워지거나 그래프 Undo가 실행됨 | 입력 칸에 포커스가 있으면 에디터 단축키를 무시하고 브라우저 기본 동작에 맡긴다. 2-b에서 손으로 확인하고, M3 끝의 e2e에 넣는다 |
