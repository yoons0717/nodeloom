# M1 core

> **상태: 완료 (2026-10-06).** 상위 문서: `docs/PROJECT_PLAN.md` 4절.

## 왜 하나

워크플로우 그래프의 모양과 규칙을 화면도 서버도 아닌 공용 패키지(`packages/core`)에 둔다. 에디터의 즉시 피드백과 서버의 최종 판정이 같은 코드라 어긋나지 않는다. 순수 TypeScript이고, React·Next·Nest·DB에 의존하지 않는다(의존성은 zod, JSONata뿐).

## 한 일

그래프 모델과 노드 스키마, 그래프 검증과 연결 판정(`canConnect`), 위상 정렬과 순환 검사, 합류·분기 판정, `{{ }}` 템플릿 나누기와 참조 추출. 규칙마다 성공·실패 케이스 테스트를 둔다.

## 정한 것

- 저장은 초안도 허용하므로 그래프 스키마는 뼈대만 엄격히 보고, 노드 설정은 검증(`validateGraph`)이 따로 본다.
- 검증 결과는 `{ code, message, nodeId?, edgeId? }` 목록이다. 메시지는 화면에 그대로 보여 줄 한국어 문장이고, 판정은 `code`로 한다.
- 참조 키 형식은 `^[a-z][a-z0-9_]*$`. 새 노드의 키는 노드 종류 기준(`http_1`)으로 자동으로 만들고 사용자가 바꿀 수 있다.
- HTTP 재시도 기본값은 0회.
- JSONata는 core 의존성으로 둔다(문법 검사를 에디터와 서버가 같이 쓴다).
- 합류 판정(`decideNode`)은 부모 상태를 받아 `run`/`skip`/`wait`만 돌려주는 순수 함수다. 저장·시간·네트워크는 다루지 않는다.
- 실패한 부모가 하나라도 있으면 성공한 부모가 있어도 건너뛴다. "하나라도 성공하면 실행"은 Condition 분기로 건너뛴 부모를 위한 규칙이다.
