# M1 core 계획

> 상위 문서: `docs/PROJECT_PLAN.md` 6절 M1. **상태: 완료 (2026-10-06).** 작은 결정: HTTP 재시도 기본 0회, 참조 키 자동 생성은 노드 종류 기준(`http_1`), JSONata는 core 의존성.

## 무엇을 만드나

워크플로우 그래프의 **모양과 규칙**을 정의한다. 화면도 서버도 아닌, 둘이 함께 쓰는 공용 코드다.

| 항목 | 내용 |
|---|---|
| 위치 | `packages/core/src/` (패키지 이름 `@nodeloom/core`) |
| 성격 | 순수 TypeScript. React, Next, Nest, DB에 의존하지 않는다. 의존성은 zod 4, JSONata 2.2만 |
| 빌드 | `tsc`로 ESM과 `.d.ts`를 `packages/core/dist/`에 출력(9-3, F-1) |
| 테스트 | 같은 폴더에 `*.test.ts`. 테스트용 예시 그래프는 `fixtures.test-util.ts`(빌드에서 제외) |

```
apps/web (Next, 프론트) ──┐
                          ├──▶ import { ... } from '@nodeloom/core'
apps/api (Nest, 서버)  ───┘
```

같은 규칙을 한 곳에서 쓰기 때문에 에디터의 즉시 피드백과 서버의 최종 판정이 어긋나지 않는다.

## 완료 기준

| 완료 기준 | 확인 방법 |
|---|---|
| 아래 작업 1~5의 규칙마다 성공 케이스와 실패 케이스 테스트가 있고 통과한다 | `pnpm --filter @nodeloom/core test` |
| core가 React, Next, Nest, DB에 의존하지 않는다 | `packages/core/package.json`의 `dependencies`가 zod와 jsonata뿐 |

| CI 통과 | GitHub Actions |

## 작업

각 작업에 **파일 위치**, **내보내는 것(export)**, **나중에 누가 쓰는지**를 적는다.

### 1. 그래프 모델과 노드 스키마
- **파일:** `packages/core/src/graph.ts`, 테스트 `graph.test.ts`
- **내용:**
  - 그래프: `{ schemaVersion, nodes, edges }` (B-8)
  - 노드: `{ id, key, type, title, position, config }`. `id`는 `crypto.randomUUID()`, `key`는 참조 키(3-4)
  - 엣지: `{ id, from: { node, port }, to: { node, port } }`
  - 노드 종류별 포트와 설정

| 종류 | 입력 포트 | 출력 포트 | 설정(기본값) |
|---|---|---|---|
| trigger | 없음 | `out` | `cron`(없음), `testInput`(`{}`) |
| http | `in` | `out` | `method`(GET), `url`(필수), `query`(`{}`), `headers`(`{}`), `body`(JSONata 식, 빈 문자열이면 본문 없음), `timeoutSec`(10, 1~30), `retry`(0, 0~5), `continueOnNon2xx`(false) |
| transform | `in` | `out` | `expression`(필수) |
| condition | `in` | `true`, `false` | `expression`(필수) |

  - 저장은 초안도 허용하므로(7-5) **그래프 스키마는 뼈대만 엄격히** 보고, 노드 설정은 작업 2의 검증이 따로 본다
  - 참조 키 형식 `^[a-z][a-z0-9_]*$`. 새 노드의 키는 `<type>_<n>`(예: `http_1`)으로 자동 생성하고 사용자가 바꿀 수 있다
- **내보내는 것:** `GRAPH_SCHEMA_VERSION`, `NODE_SPECS`, `NODE_KEY_PATTERN`, `graphSchema`, `nodeSchema`, `edgeSchema`, `nodeTypeSchema`, 타입 `Graph`·`GraphNode`·`GraphEdge`·`PortRef`·`NodeType`·`NodeConfig`, `nextNodeKey()`
- **누가 쓰나:** web(M2 팔레트에서 노드 추가, 설정 패널 폼, M3 저장 전 형식 검사), api(M3 저장 요청 형식 검사, M4 실행 시 설정 해석)

### 2. 그래프 검증
- **파일:** `packages/core/src/validate.ts`, 테스트 `validate.test.ts`
- **내용:**
  - `validateGraph(graph)`가 문제 목록 `{ code, message, nodeId?, edgeId? }[]`를 돌려준다. 메시지는 화면에 그대로 보여 줄 한국어 문장
  - 규칙(문제 `code`):

| code | 규칙 | 근거 |
|---|---|---|
| `invalid_config` | 노드 설정이 스키마에 맞지 않음 | 3-1 |
| `invalid_key` / `duplicate_key` | 참조 키 형식 오류 / 중복 | 3-4 |
| `trigger_count` | Trigger가 정확히 1개가 아님 | A-4 |
| `unreachable` | Trigger에서 이어지지 않은 노드 | A-4 |
| `cycle` | 순환 (작업 3에서 추가) | 7-1 |
| `unknown_node` | 존재하지 않는 노드로의 연결 | — |
| `invalid_port` | 없는 포트이거나 방향이 틀린 연결(출력 → 입력만 허용) | — |
| `self_loop` / `duplicate_edge` | 자기 연결 / 같은 연결 중복 | — |
| `unknown_ref` | 식이 없는 참조 키 `$nodes.<key>`를 가리킴 | 3-4 |
| `expression_syntax` | JSONata 문법 오류 | A-5 |

  - `canConnect(graph, from, to)`: 선을 놓기 전에 허용 여부와 거부 사유를 돌려준다. 순환이 생기는 연결 거부는 작업 3에서 추가
- **내보내는 것:** `validateGraph()`, `canConnect()`, 타입 `Issue`·`IssueCode`·`ConnectResult`
- **누가 쓰나:** web(M2 노드 오류 배지, React Flow `isValidConnection`과 거부 사유 표시), api(M4 수동 실행과 스케줄 실행 직전 검증, 7-5)

### 3. 위상 정렬과 순환 검증
- **파일:** `packages/core/src/topo.ts`, 테스트 `topo.test.ts`
- **내용:**
  - `topoSort(graph)`: 화살표 방향을 지킨 노드 순서. 순환이 있으면 순서 대신 순환에 걸린 노드 목록을 돌려준다
  - 작업 2에 연결: `validateGraph`에 `cycle` 규칙 추가, `canConnect`에 "이 선을 추가하면 순환이 생김" 거부 추가
- **내보내는 것:** `topoSort()`, 타입 `TopoResult`
- **누가 쓰나:** api(M4 실행 순서), web(M2 순환 연결 거부, 작업 2를 통해)

### 4. 합류와 분기 판정 (7-2)
- **파일:** `packages/core/src/flow.ts`, 테스트 `flow.test.ts`
- **내용:**
  - `decideNode(nodeId, graph, states)`: 부모 노드들의 상태를 보고 이 노드를 `run` / `skip` / `wait` 중 무엇으로 할지 판정
    - 부모 상태: `pending` / `running` / `success` / `failed` / `skipped`. Condition 부모는 성공할 때 어느 포트(`true`/`false`)로 나갔는지도 함께 기록
    - 선택되지 않은 Condition 포트에서 온 연결은 SKIPPED로 취급
    - 부모가 하나: 성공이면 `run`, SKIPPED·FAILED면 `skip`, 아직 끝나지 않았으면 `wait`
    - 부모가 여럿: 하나라도 끝나지 않았으면 `wait`, 모두 끝났고 성공이 하나 이상이면 `run`, 아니면 `skip`
    - 실패한 부모가 하나라도 있으면 `skip`(7-4: 실패한 노드의 하위 노드는 SKIPPED)
  - `buildInput(nodeId, graph, states, outputs)`: 노드의 입력(루트). 부모가 하나면 그 출력, 여럿이면 성공한 부모만 `{ 참조키: 출력 }`
  - 상태를 받아 판정만 돌려주는 순수 함수. 저장, 시간, 네트워크는 다루지 않는다
- **내보내는 것:** `decideNode()`, `buildInput()`, 타입 `NodeRunState`·`NodeRunStatus`·`Decision`
- **누가 쓰나:** api(M4 실행 엔진이 노드마다 반복 호출), web(M5 실행 상세 화면은 저장된 상태를 그대로 보여 주므로 직접 쓰지 않음)

### 5. 템플릿과 참조 추출
- **파일:** `packages/core/src/template.ts`, 테스트 `template.test.ts`
- **내용:**
  - `parseTemplate(text)`: 문자열 칸(URL, 헤더, 쿼리)의 `{{ 식 }}` 구간을 나눈다
  - `extractNodeRefs(expr)`: 식에서 `$nodes.<key>` 참조를 뽑는다
  - `checkExpressionSyntax(expr)`: JSONata 문법 검사(오류 메시지와 위치)
  - `nodeExpressions(node)`: 노드 설정에서 검사할 식을 모두 꺼낸다(작업 2가 사용)
- **내보내는 것:** 위 네 함수, 타입 `TemplatePart`·`ExpressionSyntaxError`
- **누가 쓰나:** web(M2 설정 패널 문법 오류 표시), api(M4 `{{ }}` 치환 후 실행)

## 위험과 대응

| 위험 | 대응 |
|---|---|
| 검증 규칙이 늘면서 문제 목록 형식이 흔들림 | `code` 목록을 먼저 고정하고, 테스트는 `code`로 판정 |
