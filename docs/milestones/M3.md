# M3 저장·인증·데모 계획

> 상위 문서: `docs/PROJECT_PLAN.md` 6절 M3. **상태: 승인됨 (2026-10-07).** 작은 결정 ①~⑧은 기본값으로 확정(⑦로 보류 중이던 10-3a도 확정).

## 무엇을 만드나

M2의 에디터를 **서버에 저장하고 다시 불러오게** 만든다. 개인 서버는 관리자 한 명만 로그인해서 쓰고, 공개 데모(`DEMO_MODE=true`)는 로그인 없이 누구나 편집할 수 있게 한다. 처음으로 web과 api, DB가 함께 동작하는 단계다.

| 항목 | 내용 |
|---|---|
| 위치 | `apps/api/`(저장 API, 인증, 데모 규칙, DB 모델), `apps/web/`(로그인, 목록, 에디터 저장·불러오기), `apps/browser-tests/`(e2e 시작) |
| 새로 쓰는 것 | Prisma 마이그레이션, `@nestjs/jwt`, `@nestjs/throttler`, `helmet`, `cookie-parser`, bcrypt(작은 결정 ①), TanStack Query(4-2) |
| 쓰지 않는 것 | 실행 엔진, pg-boss, `runs`·`node_runs` 테이블(M5) |

## 완료 기준

| 완료 기준 | 확인 방법 |
|---|---|
| 저장한 워크플로우가 새로고침 뒤에도 그대로 복원된다 | e2e 시나리오 1 |
| 로그인하지 않으면 목록, 에디터, API에 접근할 수 없다(데모 제외) | api 통합 테스트, e2e |
| 데모 모드 규칙(로그인 없이 접근, 관리자 로그인 꺼짐, 개수·크기 상한)이 통합 테스트로 확인된다 | `pnpm --filter @nodeloom/api test` |
| e2e 두 개가 통과하고 CI에서 돈다(H-1) | ① 로그인 → 노드 추가 → 연결 → 순환 연결 거부 → Undo → 저장 → 새로고침 후 복원 ② 데모 모드에서 로그인 없이 편집. GitHub Actions |
| 전체 lint, 타입 체크, 테스트, 빌드와 CI가 통과한다 | `pnpm turbo run lint typecheck test build`, GitHub Actions |

## 화면 구성

| 경로 | 화면 | 렌더링 |
|---|---|---|
| `/login` | 비밀번호 하나 입력. 데모 모드에서는 목록으로 보냄 | 서버 컴포넌트 + 제출 폼 |
| `/` | 워크플로우 목록(이름, 노드 수, 마지막 수정 시각), 새로 만들기, 삭제, 로그아웃 | 서버 컴포넌트(4-1) |
| `/w/:id` | M2 에디터 + 상단 바에 이름 편집, 저장 버튼, 저장 안 된 변경 표시 | 서버 컴포넌트가 그래프를 불러와 클라이언트 에디터에 넘김 |

- M2의 `/editor`는 없앤다(작은 결정 ⑤). `/bench`는 그대로 둔다.
- 좁은 화면(B-11): 목록은 그대로 보여 주고, 에디터 자리에는 "데스크톱에서 열어 주세요" 안내를 띄운다.
- 시각은 `APP_TIMEZONE`으로 서버와 브라우저가 같게 표시한다(hydration 불일치 방지).

## API

브라우저는 `/api/*`만 부르고 Next rewrites가 NestJS로 넘긴다(6-4). NestJS 경로에는 `/api`가 붙지 않는다.

| 메서드와 경로 | 하는 일 | 인증 |
|---|---|---|
| `POST /auth/login` | 비밀번호를 bcrypt로 비교하고 JWT 쿠키 발급(7일, `httpOnly`, `SameSite=Lax`, 운영에서 `Secure`) | 없음. IP별 속도 제한. 데모 모드에서는 403 |
| `POST /auth/logout` | 쿠키 삭제 | 필요 |
| `GET /auth/me` | 지금 사용자 역할(`admin` 또는 `demo`) | 필요 |
| `GET /workflows` | 목록(이름, 노드 수, 수정 시각) | 필요 |
| `POST /workflows` | 새로 만들기. `{ name, graph }` | 필요 |
| `GET /workflows/:id` | 이름과 그래프 | 필요 |
| `PUT /workflows/:id` | 덮어쓰기 저장(2-4). 409 없음 | 필요 |
| `DELETE /workflows/:id` | 삭제. 실행 기록과 엮인 규칙(B-4)은 M5에서 | 필요 |
| `GET /health` | 기존 그대로 | 없음 |

- **인증:** 전역 Guard가 쿠키의 JWT를 확인한다. `DEMO_MODE`면 쿠키 없이도 demo 사용자로 본다(B-6). `/health`와 `/auth/login`만 예외.
- **저장 검증:** 그래프는 core의 `graphSchema`(뼈대)로만 검사한다. 설정 오류, 순환 같은 검증 오류가 있어도 저장은 허용한다(7-5 초안 저장). 뼈대가 깨진 요청만 400.
- **데모 상한(8-3):** 워크플로우 개수, 그래프 노드 수, 요청 크기, 전체 API 속도 제한. 숫자는 작은 결정 ②.
- **helmet:** 기본 설정. CORS는 쓰지 않는다(같은 출처).

### 데이터

```prisma
model Workflow {
  id        String   @id @default(uuid())
  name      String
  graph     Json      // core graphSchema 형식, schemaVersion 포함
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  @@map("workflows")
}
```

사용자 테이블은 만들지 않는다(관리자 한 명, 2-2). 실패 알림 대상 칼럼은 그 기능을 만드는 M5에서 추가한다.

### 환경 변수 (추가)

| 이름 | 내용 |
|---|---|
| `ADMIN_PASSWORD_HASH` | bcrypt 해시(D-4). `pnpm admin:hash`가 만들고, Compose용 `$$` 형태도 함께 출력(E-2) |
| `JWT_SECRET` | 서명 키. 바꾸면 모든 로그인이 풀린다(B-3) |
| `DEMO_MODE` | `true`면 데모 모드 |
| `APP_TIMEZONE` | 화면 시각 표시용(기본 `Asia/Seoul`) |

`DEMO_MODE`가 아니면 `ADMIN_PASSWORD_HASH`와 `JWT_SECRET`이 없을 때 서버가 시작하지 않는다(`env.ts`의 zod 검사).

## 단계

네 단계로 나누고 단계마다 보고하고 멈춘다.

### 3-a. DB와 저장 API (화면 없음)
- **파일:** `apps/api/prisma/schema.prisma`, `prisma/migrations/`, `src/workflows/`(module, controller, service, dto), 통합 테스트
- **첫 작업:** Prisma 7 마이그레이션이 설치 스크립트 차단 정책(`allowBuilds`에서 `@prisma/engines: false`)으로 동작하는지 확인. 안 되면 `@prisma/engines`만 허용하고 DECISIONS에 기록(M0에서 미뤄 둔 항목)
- **내용:** `Workflow` 모델, CRUD, zod로 요청 검사(`graphSchema`), 없는 id는 404
- **테스트(Testcontainers):** 만들기 → 불러오기 → 덮어쓰기 → 삭제, 검증 오류가 있는 그래프도 저장됨, 뼈대가 깨진 그래프는 400. 통합 테스트용 DB에는 마이그레이션을 적용해서 시작한다
- **이 단계에서는 인증 없이 동작한다.** 3-b에서 Guard를 씌운다

### 3-b. 인증과 데모 모드
- **파일:** `src/auth/`(controller, service, guard), `src/demo/`(상한 검사), `src/env.ts`, `src/main.ts`(helmet, cookie-parser), `scripts/admin-hash.ts`, 루트 `package.json`의 `admin:hash`
- **내용:**
  - 로그인·로그아웃·`me`, 전역 JWT Guard, 로그인 속도 제한(`@nestjs/throttler`)
  - `DEMO_MODE`: 쿠키 없이 demo로 간주, 로그인 403, 상한 검사, 전체 속도 제한
  - `pnpm admin:hash`: 비밀번호를 입력받아 해시와 `$$` 형태를 출력. `.env.example`에 경고 주석
- **테스트(Testcontainers):** 로그인 성공·실패, 쿠키 속성, 쿠키 없으면 401, 만료·변조 토큰 401, 속도 제한 초과 429, 데모 모드에서 쿠키 없이 접근 가능, 데모에서 로그인 403, 데모 상한 초과 거부

### 3-c. 화면: 로그인, 목록, 저장·불러오기
- **파일:** `apps/web/src/app/login/`, `app/page.tsx`(목록), `app/w/[id]/page.tsx`, `src/lib/api.ts`(서버 컴포넌트용 API 호출), `features/workflows/`(목록, 새로 만들기, 삭제), `features/editor/`(저장 버튼, 이름 편집, 저장 안 된 변경 표시)
- **내용:**
  - 서버 컴포넌트는 브라우저 쿠키를 실어 NestJS를 직접 부르고(6-4), 401이면 `/login`으로 보낸다(작은 결정 ⑥)
  - 로그인 폼은 기본 `<form>` + zod `safeParse`(4-4)
  - 저장은 TanStack Query mutation. 저장 버튼과 ⌘S, 저장 안 된 변경이 있으면 상단 바에 표시하고 떠날 때 확인(작은 결정 ④)
  - 저장 안 된 변경은 "마지막으로 저장한 그래프 객체"와 지금 그래프 객체를 비교해서 판단(불변 갱신이라 객체 비교로 충분)
  - 새로 만들기는 core 기준의 첫 그래프(Trigger 하나)로 `POST` 후 `/w/:id`로 이동
  - 좁은 화면 안내(B-11)
- **테스트:** 저장 안 된 변경 판단과 저장 후 초기화를 RTL 또는 단위 테스트 1~2개

### 3-d. e2e 시작
- **파일:** `apps/browser-tests/e2e/*.e2e.ts`, `playwright.config.ts`(벤치와 e2e를 project로 나눔), `.github/workflows/ci.yml`(e2e 작업 추가)
- **내용:**
  - 시나리오 ① 로그인 → 노드 추가 → 연결 → 순환 연결 거부 → Undo → 저장 → 새로고침 후 복원
  - 시나리오 ② 데모 모드에서 로그인 없이 목록 → 새로 만들기 → 편집 → 저장
  - 두 시나리오는 서버 설정(`DEMO_MODE`)이 달라서, api를 두 벌 띄우거나 시나리오별로 따로 띄운다
  - CI: Postgres 서비스 컨테이너 + 마이그레이션 + api·web 프로덕션 빌드를 띄워 e2e 실행(작은 결정 ⑦)
- M2의 "입력 칸에서 Backspace로 노드가 지워지지 않는다"도 시나리오 ①에 한 단계로 넣는다

## 작은 결정 (승인 시 함께 확정)

| # | 질문 | 기본값 | 대안 |
|---|---|---|---|
| ① | bcrypt 라이브러리 | `bcryptjs`(순수 JS, 설치 스크립트 없음) | `bcrypt`(네이티브, 빠르지만 `allowBuilds` 허용과 빌드 도구 필요) |
| ② | 상한 숫자 | 로그인 IP당 1분 5회. 데모: 워크플로우 20개, 그래프 노드 100개, 요청 본문 256KB, 전체 API IP당 1분 120회 | 더 느슨하게 / 더 엄격하게 |
| ③ | 워크플로우 이름 | 필수, 1~100자, 새로 만들 때 "새 워크플로우" | 이름 없이 허용 |
| ④ | 저장 방식 | 저장 버튼 + ⌘S, 저장 안 된 변경 표시, 떠날 때 확인 | 자동 저장(디바운스) |
| ⑤ | M2의 `/editor` | 삭제 | `/`로 리다이렉트 |
| ⑥ | web의 인증 확인 위치 | 서버 컴포넌트에서 API를 부를 때(401이면 `/login`). 실제 검사는 NestJS Guard 하나 | Next Proxy에서 쿠키 유무를 먼저 확인(빠른 리다이렉트, 코드 한 곳 더) |
| ⑦ | e2e를 CI에서 돌리는 시점(10-3a) | 모든 push에서, 기존 검사와 별도 작업으로 | 수동 실행만 / main 브랜치에만 |
| ⑧ | 삭제 확인 | 목록에서 삭제할 때 화면 안 확인 단계 | 확인 없이 삭제 |

## 위험과 대응

| 위험 | 대응 |
|---|---|
| Prisma 7 마이그레이션이 설치 스크립트 차단 때문에 엔진을 못 받음 | 3-a 첫 작업으로 확인. 안 되면 `@prisma/engines`만 허용 |
| 로컬 http에서 `Secure` 쿠키가 저장되지 않음 | `Secure`는 운영(`NODE_ENV=production`)에서만 켠다. 브라우저는 `localhost`를 안전한 출처로 봐서 대부분 문제없지만, 쿠키 속성 테스트로 확인 |
| 서버 컴포넌트에서 NestJS를 부를 때 쿠키를 안 실음 | `src/lib/api.ts` 한 곳에서만 부르고, 쿠키를 싣는 것을 그 함수가 맡는다 |
| e2e가 CI에서 느리거나 불안정함 | 시나리오 2개만, 프로덕션 빌드로, 재시도 1회. 실패하면 Playwright trace를 아티팩트로 남김 |
| 데모 모드와 일반 모드를 같은 e2e 실행에서 다뤄야 함 | Playwright project를 나누고 project마다 서버를 따로 띄움. 복잡하면 데모 시나리오를 별도 명령으로 분리 |
| 저장 안 된 변경을 잃음(새로고침, 뒤로 가기) | 떠날 때 확인(작은 결정 ④). 자동 저장은 하지 않음 |
