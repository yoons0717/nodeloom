# M3 저장·인증·데모

> **상태: 완료 (2026-10-07).** 상위 문서: `docs/PROJECT_PLAN.md` 4절.

## 왜 하나

M2의 에디터를 서버에 저장하고 다시 불러오게 만든다. 개인 서버는 관리자 한 명만 로그인해서 쓰고, 데모 모드(`DEMO_MODE=true`)는 로그인 없이 누구나 편집할 수 있게 한다. web과 api, DB가 처음으로 함께 동작하는 단계다.

## 한 일

워크플로우 저장 API와 DB 모델, 관리자 로그인과 데모 모드, 로그인·목록·에디터 저장 화면, 첫 e2e 두 개(관리자 흐름, 데모 흐름).

## 만들면서 정한 것

- **인증:** 전역 Guard가 쿠키의 JWT를 확인한다. 데모 모드에서는 쿠키 없이도 demo 사용자로 보고, 관리자 로그인은 403이다. `/health`와 `/auth/login`만 예외다. 쿠키는 7일, `httpOnly`, `SameSite=Lax`, 운영에서 `Secure`.
- **저장 검증:** 그래프는 core의 뼈대 스키마로만 검사한다. 설정 오류나 순환이 있어도 저장한다(초안). 뼈대가 깨진 요청만 400.
- **사용자 테이블 없음:** 관리자는 한 명이고 비밀번호 해시는 환경 변수(`ADMIN_PASSWORD_HASH`)에 둔다. 데모 모드가 아니면 해시나 `JWT_SECRET`이 없을 때 서버가 시작하지 않는다.
- **저장하지 않은 변경:** 마지막으로 저장한 그래프 객체와 지금 그래프 객체를 비교한다. 불변 갱신이라 객체 비교로 충분하다.
- **CORS 없음:** 브라우저는 `/api/*`만 부르고 Next rewrites가 NestJS로 넘긴다(같은 출처).
- **e2e:** 관리자와 데모는 서버 설정이 달라 `E2E_MODE`로 나눠 두 번 실행한다. 실행마다 Testcontainers로 새 Postgres를 띄워 개발 DB를 건드리지 않는다.

## 정한 것

| # | 질문 | 정한 것 | 검토한 대안 |
|---|---|---|---|
| ① | bcrypt 라이브러리 | `bcryptjs`(순수 JS, 설치 스크립트 없음) | `bcrypt`(네이티브, 빠르지만 `allowBuilds` 허용과 빌드 도구 필요) |
| ② | 상한 숫자 | 로그인 IP당 1분 5회. 데모: 워크플로우 20개, 그래프 노드 100개, 요청 본문 256KB, 전체 API IP당 1분 120회 | 더 느슨하게 / 더 엄격하게 |
| ③ | 워크플로우 이름 | 필수, 1~100자, 새로 만들 때 "새 워크플로우" | 이름 없이 허용 |
| ④ | 저장 방식 | 저장 버튼 + ⌘S, 저장하지 않은 변경 표시, 떠날 때 확인 | 자동 저장(디바운스) |
| ⑤ | M2의 `/editor` | 삭제 | `/`로 리다이렉트 |
| ⑥ | web의 인증 확인 위치 | 서버 컴포넌트에서 API를 부를 때(401이면 `/login`). 실제 검사는 NestJS Guard 하나 | Next Proxy에서 쿠키 유무를 먼저 확인(빠른 리다이렉트, 코드 한 곳 더) |
| ⑦ | e2e를 CI에서 돌리는 시점 | 모든 push에서, 기존 검사와 별도 작업으로 | 수동 실행만 / main 브랜치에만 |
| ⑧ | 삭제 확인 | 목록에서 삭제할 때 화면 안 확인 단계 | 확인 없이 삭제 |
