## README 구성

1. **소개:** 한 줄 소개와 할 수 있는 일
   - 노드 4종(Trigger, HTTP 요청, Transform, Condition)을 이어 흐름 만들기, 연결 검증과 거부 사유, Undo/Redo
   - 서버가 흐름 실행: 분기·합류, 재시도·시간 제한, 실패하면 다른 흐름으로 알림
   - 정해진 시각 실행(반복 선택), 실행 기록과 노드별 입출력
   - 비밀값 가리기, 내부망 요청 차단, 로그인 없이 써 보는 데모 모드
2. **화면:** 이미지 3장. 에디터, 실행 상세(노드 상태와 입출력), 워크플로우 목록(스케줄 표시)
3. **구조:** 그림 두 개
   - 구성: 브라우저 → Next(web) → `/api` 중계 → NestJS(api, 실행 워커, 스케줄러) → Postgres(+ pg-boss). web과 api가 core(그래프 규칙, 검증, 식 계산)를 함께 쓴다
   - 실행 흐름: 실행 버튼 → 실행 기록과 job을 한 트랜잭션으로 → 워커가 노드 실행 → 노드별 결과 저장 → 화면은 1초마다 상태 조회
   - 아래에 주요 기술 선택과 이유를 한 줄씩(5~6개)
4. **실행 방법, 명령:** 지금 내용을 유지하고 새로 clone해서 확인한 결과대로 고친다
5. **한계**
   - 최소 한 번 실행: 요청을 보낸 직후 결과를 저장하기 전에 서버가 죽으면, 이어서 실행할 때 같은 요청을 다시 보낼 수 있다
   - 비밀값 가리기는 원래 값, URL 인코딩, JSON 문자열 형태만 찾는다. Base64 등 다른 형태로 바꾼 값은 기록에 남을 수 있다
   - 서버가 꺼져 있던 동안의 스케줄 회차는 실행하지 않는다
   - 시간대는 `APP_TIMEZONE` 하나다. 웹은 빌드할 때 값이 정해지고, 바꾸면 이미 저장한 스케줄은 다시 저장해야 새 시간대로 돈다
   - 사용자는 관리자 1명이다. 같은 워크플로우는 한 번에 하나만 실행한다
6. **문서:** 저장소에 있는 문서만 링크한다(④)
