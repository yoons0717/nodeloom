# M0 기반

> **상태: 완료 (2026-10-06).** 상위 문서: `docs/PROJECT_PLAN.md` 4절.

## 왜 하나

모노레포 뼈대를 세우고 web, api, core가 함께 뜨게 한다. 브라우저 → Next → NestJS → DB(`/api/health`)가 이어지고, CI(lint, 타입 체크, 테스트, 빌드)가 통과하는 데까지.

## 버전을 고른 이유

| 도구 | 버전 | 이유 |
|---|---|---|
| Node.js | 24 LTS(`.nvmrc`, `engines`) | 2028년 4월까지 지원. NestJS 12 CLI는 24.15 이상 필요 |
| pnpm | 12, Corepack으로 설치 | Node 24에 Corepack이 들어 있다 |
| Prisma | 7 | npm `latest`가 8 RC를 가리켜 명시 고정 |
| TypeScript | 6.0.3 | typescript-eslint가 6.1 미만을 지원. TS 7은 제외 |
| ESLint | 9 | `eslint-config-next`가 쓰는 플러그인이 아직 ESLint 10을 지원하지 않는다 |
| Vitest | 4 | Nest 12 템플릿에 맞춰 core까지 통일 |
| 포맷 | Prettier + `eslint-config-prettier` | 린터와 역할을 나눈다 |

## M0에서 확인한 것

| 확인할 것 | 결과 |
|---|---|
| Next rewrites가 api 응답의 `Set-Cookie`를 브라우저로 전달하는지 | 전달한다. 같은 출처 쿠키로 로그인을 만들 수 있다 |
| GitHub Actions에서 Testcontainers가 동작하는지 | 기본 Ubuntu 실행 환경의 Docker로 동작한다 |
| Nest 12 ESM + Vitest의 데코레이터 메타데이터 | 템플릿 기본 Vitest 4 설정으로 생성자 주입이 동작한다. `unplugin-swc`는 필요 없다 |

## 만들면서 정한 것

- 환경 변수는 루트 `.env` 하나를 쓰고, 각 앱이 Node 내장 `process.loadEnvFile`로 읽는다(dotenv 없음). api는 시작할 때 zod로 검사하고, 없으면 바로 종료한다.
- Prisma 7은 드라이버 어댑터(`@prisma/adapter-pg`)로 연결한다. 생성 클라이언트는 커밋하지 않고, Turborepo `generate` 작업이 다른 작업보다 먼저 실행된다.
- Nest 템플릿의 oxlint는 빼고 루트 ESLint 설정 하나(타입 정보 규칙 포함)를 쓴다.
