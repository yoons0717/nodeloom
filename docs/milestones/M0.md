# M0 기반

> **상태: 완료 (2026-10-06).** 상위 문서: `docs/PROJECT_PLAN.md` 4절.

## 목표

모노레포 뼈대를 세우고 web, api, core가 함께 뜨게 한다.

| 완료 기준 | 확인 방법 |
|---|---|
| `pnpm install` → `docker compose up -d` → `pnpm dev`로 web과 api가 함께 뜬다 | 세 명령을 처음부터 순서대로 실행 |
| 브라우저에서 Next를 거쳐 `/api/health`가 DB 정상을 반환한다 | `http://localhost:3000/api/health` 응답 확인 |
| web과 api가 `@nodeloom/core`를 import해서 쓴다 | 두 앱이 core의 값을 쓰는 코드가 빌드와 테스트를 통과 |
| CI(lint, 타입 체크, 테스트, 빌드)가 통과한다 | GitHub Actions |

## 한 일

- **루트:** pnpm workspace(`apps/*`, `packages/*`), `turbo.json`(`build`는 의존 패키지 먼저, `lint`·`typecheck`·`test`는 `^build`에 의존, `dev`는 캐시 없음), `tsconfig.base.json`(strict, `NodeNext`. web은 Next 권장값으로 덮어씀), 루트 ESLint flat config 하나(타입 정보 규칙 포함)
- **`packages/core`:** ESM 패키지, `tsc`로 `dist`에 JS와 `.d.ts` 출력. 첫 내용은 `GRAPH_SCHEMA_VERSION = 1`
- **`apps/api`:** `nest new` ESM 템플릿(템플릿의 oxlint는 빼고 루트 ESLint 사용), Prisma 7, 시작할 때 zod로 환경 변수 검사(없으면 즉시 종료), `GET /health`(`SELECT 1`로 DB 확인, 응답에 `GRAPH_SCHEMA_VERSION`). Testcontainers로 Postgres를 띄운 통합 테스트
- **`apps/web`:** `create-next-app`(App Router, Tailwind 4), `/api/:path*`를 api로 넘기는 rewrites, 첫 페이지에 `GRAPH_SCHEMA_VERSION` 표시
- **로컬 DB:** `docker-compose.yml`(postgres 18, 이름 있는 볼륨, healthcheck), `.env.example`
- **CI:** `.github/workflows/ci.yml`. push와 PR에서 `pnpm install --frozen-lockfile` → `prisma generate` → `turbo run lint typecheck test build`

## 시작 전 확인한 것

| 확인할 것 | 결과 |
|---|---|
| Next rewrites가 api 응답의 `Set-Cookie`를 브라우저로 전달하는지 | 전달한다. 같은 출처 쿠키로 로그인을 만들 수 있다 |
| GitHub Actions에서 Testcontainers가 동작하는지 | 기본 Ubuntu 실행 환경의 Docker로 동작한다 |
| Nest 12 ESM + Vitest의 데코레이터 메타데이터 | 템플릿 기본 Vitest 4 설정으로 생성자 주입이 동작한다. `unplugin-swc`는 필요 없다 |

## 만들면서 정한 것

- ESLint는 9로 고정했다. `eslint-config-next`가 쓰는 플러그인이 아직 ESLint 10을 지원하지 않는다.
- Vitest는 Nest 12 템플릿에 맞춰 4로 통일했다(core 포함).
- 환경 변수는 루트 `.env` 하나를 쓰고, 각 앱이 Node 내장 `process.loadEnvFile`로 읽는다(dotenv 없음).
- Prisma 7은 드라이버 어댑터(`@prisma/adapter-pg`)로 연결한다. 생성 클라이언트는 `apps/api/src/generated/`에 두고 커밋하지 않으며, Turborepo `generate` 작업이 다른 작업보다 먼저 돈다.
