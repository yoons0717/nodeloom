# M0 기반 세팅 계획

> 상위 문서: `docs/PROJECT_PLAN.md` 6절 M0.
> **상태: 완료 (2026-10-06).** 작은 결정 S-1~S-6 확정(S-2는 pnpm 12, S-3은 비공개 저장소로 수정). 확인 결과는 `docs/DECISIONS.md`의 "M0 확인 결과".

## 목표와 완료 기준

| 완료 기준 | 확인 방법 |
|---|---|
| `pnpm install` → `docker compose up -d` → `pnpm dev`로 web과 api가 함께 뜬다 | 세 명령을 처음부터 순서대로 실행 |
| 브라우저에서 Next를 거쳐 `/api/health`가 DB 정상을 반환한다 | `http://localhost:3000/api/health` 응답 확인 |
| web과 api가 `@nodeloom/core`를 import해서 쓴다 | 두 앱 모두 core의 값을 사용하는 코드가 빌드와 테스트를 통과 |
| CI(lint, 타입 체크, 테스트, 빌드)가 GitHub Actions에서 통과한다 | 첫 push 후 Actions 결과 |
| 확인 목록 M0 항목 3개의 결과가 `DECISIONS.md`에 기록된다 | 문서 확인 |

## 작업 순서

각 단계는 끝날 때 "확인"을 통과해야 다음으로 넘어간다.

### 1. 저장소와 루트 설정
- `git init`, `.gitignore`(node_modules, dist, .next, .env, coverage, .turbo)
- `.nvmrc`(24), 루트 `package.json`(`private`, `packageManager`, `engines`, `type: module`)
- `pnpm-workspace.yaml`: `apps/*`, `packages/*`
- `turbo.json` 작업:
  - `build`: 의존 패키지 먼저(`^build`), 출력 `dist/**`, `.next/**`
  - `dev`: 캐시 없음, 계속 실행
  - `lint`, `typecheck`, `test`: `^build`에 의존
- `tsconfig.base.json`: `strict`, ES2023, `module`과 `moduleResolution`은 `NodeNext`(core, api용). web은 Next 권장값(`moduleResolution: bundler`)으로 자기 tsconfig에서 덮어쓴다
- `eslint.config.mjs`(F-2): typescript-eslint 타입 정보 규칙, 앱별 확장은 각 앱 설정에서
- Prettier 설정(S-5)
- **확인:** `pnpm install`이 경고 없이 끝난다

### 2. `packages/core`
- ESM 패키지(`type: module`, `exports`), `tsc`로 `dist`에 JS와 `.d.ts` 출력(F-1)
- 첫 내용은 **그래프 형식 버전 상수 `GRAPH_SCHEMA_VERSION = 1`** 하나(B-8에서 실제로 쓰일 값). M1 기능은 만들지 않는다
- Vitest 설정과 테스트 1개
- **확인:** `pnpm --filter @nodeloom/core build`와 `test` 통과

### 3. `apps/api` (NestJS 12)
- `nest new`를 ESM 템플릿으로 생성(pnpm, git 초기화 생략). 템플릿의 oxlint는 제거하고 루트 ESLint를 사용(F-2)
- Prisma 7 초기화(기본 ESM 출력, 6-2). 모델은 아직 없음. `DATABASE_URL`은 환경 변수
- 환경 변수 검증: 시작할 때 zod로 `DATABASE_URL`, `PORT`를 검사하고 없으면 즉시 종료
- `GET /health`: Prisma로 `SELECT 1`을 실행해 `{ status: "ok", db: "ok" }` 또는 503을 반환. 응답에 `GRAPH_SCHEMA_VERSION`을 포함해서 core 연결을 증명
- 테스트:
  - 단위: health 서비스
  - 통합: **Testcontainers**로 Postgres 18을 띄워 `/health`가 200을 반환(10-2)
  - 데코레이터 메타데이터가 Vitest에서 동작하는지 확인. 안 되면 `unplugin-swc` 추가(F-1)
- **확인:** `pnpm --filter @nodeloom/api test` 통과, `pnpm --filter @nodeloom/api dev` 후 `curl localhost:4000/health`

### 4. `apps/web` (Next.js 16)
- `create-next-app`: TypeScript, App Router, Tailwind v4, ESLint(루트 설정으로 통합)
- `next.config`의 rewrites: `/api/:path*` → `${API_URL}/:path*`(6-4)
- 첫 페이지(서버 컴포넌트)가 `GRAPH_SCHEMA_VERSION`을 표시해서 core 연결을 증명
- web의 Vitest 설정은 첫 테스트가 생기는 M2에서 추가한다(M0의 web은 lint, 타입 체크, 빌드만)
- shadcn/ui, Zustand, React Flow는 **설치하지 않음**(M2·M3에서 필요할 때)
- **확인:** `pnpm dev`(루트) 후 `http://localhost:3000/api/health` 응답 확인

### 5. 로컬 DB와 환경 변수
- `docker-compose.yml`: `postgres:18`, 이름 있는 볼륨, healthcheck
- `.env.example`: `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`(compose용), `DATABASE_URL`, `PORT`, `API_URL`. 지금 쓰는 값만 적는다(나머지는 해당 마일스톤에서 추가)
- **확인:** 새 터미널에서 완료 기준 첫 줄을 처음부터 재현

### 6. CI
- **커밋과 push는 이 시점에 확인받는다.** 커밋 전에 변경 사항 점검 결과를 먼저 보고한다. 첫 push 전에 GitHub 저장소 이름과 공개 여부(S-3)를 다시 확인한다
- `.github/workflows/ci.yml`: push와 PR에서 실행
  - Node 24, pnpm 설치, `pnpm install --frozen-lockfile`
  - `prisma generate`
  - `turbo run lint typecheck test build`
  - Testcontainers는 GitHub 기본 Ubuntu 실행 환경의 Docker를 사용
- **확인:** 첫 push 후 Actions 통과

## 위험과 대응

| 위험 | 대응 |
|---|---|
| ESM에서 상대 import에 `.js` 확장자 누락 | `NodeNext` 설정이 컴파일 단계에서 잡아낸다 |
| Nest 12 ESM 템플릿과 Vitest의 데코레이터 메타데이터 | 3단계에서 확인. 안 되면 `unplugin-swc` |
| `pnpm dev`에서 core 변경이 앱에 늦게 반영 | core는 `tsc --watch`를 Turborepo dev 작업에 포함(9-3) |
| 생성 도구(`nest new`, `create-next-app`)가 자체 git, lockfile, 린트 설정을 만듦 | 생성 옵션으로 끄거나 생성 직후 정리하고, 루트 설정만 남긴다 |
| 루트 ESLint 설정에서 Next 규칙이 web 폴더를 못 찾음 | `eslint-config-next`의 rootDir 설정을 `apps/web`으로 지정 |
| Corepack이 pnpm 11 설치에 실패(서명 키 등) | S-2 대안(`npm i -g pnpm`)으로 전환하고 기록 |
