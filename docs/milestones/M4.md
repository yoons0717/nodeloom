# M4 실행 엔진

> **상태: 완료 (2026-10-09).** 상위 문서: `docs/PROJECT_PLAN.md` 4절. 만들면서 ③ 재개 방식을 heartbeat로 바꾸고 ④ pino 도입은 취소했다(아래 "정한 것" 표).

## 왜 하나

에디터에서 실행 버튼을 누르면 서버가 흐름을 실제로 실행하게 만든다. 노드 4종이 실제로 동작하고(HTTP 요청, 식 계산, 참·거짓 갈래), 노드마다 받은 값과 내보낸 값을 기록한다. 실행이 실패하면 지정한 "실패 알림" 흐름을 실행한다. 외부 요청 보안(SSRF)과 비밀값 가리기를 함께 넣는다.

직접 확인은 디스코드 채널로 메시지를 보내는 흐름으로 했다(웹훅 주소를 `NODELOOM_SECRET_DISCORD_WEBHOOK`에 두고 `$secrets`로 참조). 자동 테스트와 CI는 연습용 응답(`/mock/*`)으로 돌린다.

## 시작 전 확인 (2026-10-07)

| 확인할 것 | 결과 |
|---|---|
| pg-boss를 Prisma 트랜잭션 안에서 쓸 수 있는지 | 됨. `send()`의 `db` 옵션과 Prisma 트랜잭션 어댑터로 실행 기록 생성과 job 등록을 한 트랜잭션으로 묶는다 |
| JSONata 가드레일 | 됨. 2.2.2의 `timeout`, `stack` 옵션이 무한 재귀와 오래 걸리는 식을 끊는다(오류 코드 D1012) |
| pg-boss의 ESM 호환 | 됨. 정해진 시각 실행의 시간대(`tz`)도 지원(M5에서 사용) |

## 만들면서 정한 것

- **실행 시작:** 검사 실패는 422, 이미 실행 중이면 409, 시작하면 202. 화면은 1초마다 상태만 조회한다.
- **동시 실행 제한:** `runs`에 "같은 워크플로우에서 PENDING·RUNNING은 하나만, 실패 알림 실행은 제외"인 부분 유니크 인덱스를 건다. Prisma 스키마로 표현할 수 없어 마이그레이션 SQL에 직접 쓴다.
- **실패 알림:** 실패 알림 흐름이 검사에 걸리거나 실행 중 실패해도 FAILED로 기록만 하고 다시 알리지 않는다(연쇄 없음). 알림 흐름의 Trigger는 `{ workflow, runId, failedNode, error }`를 내보낸다(2026-10-18에 `failedNodeTitle` 추가).
- **Condition:** 결과가 정확히 `true`·`false`가 아니면 실패.
- **HTTP 요청:** 2xx가 아니면 실패. "다음 노드로 진행"이 켜져 있으면 응답 코드와 상관없이 `{ status, body }`, 꺼져 있으면 본문만 내보낸다. 응답은 1MB까지. 재시도는 1·2·4초…(최대 30초)에 흔들림(jitter)을 더하고 job 안에서 반복한다.
- **식 계산:** 앞 노드 결과가 루트, `$nodes.<참조 키>`, `$run`, `$secrets`를 넘긴다. `{{ }}` 안의 값이 없으면 빈 문자열로 채운다.
- **SSRF:** http·https만. 연결 직전에 실제 IP를 검사해(DNS를 바꿔치기해도) loopback·사설·링크 로컬을 막는다. 예외는 `HTTP_ALLOW_PRIVATE`와 `MOCK_BASE_URL`뿐이고, 클라우드 메타데이터 주소는 항상 막는다. 리다이렉트는 따라가지 않는다. 데모 모드에서는 `MOCK_BASE_URL`만 허용한다.
- **비밀값:** `NODELOOM_SECRET_*` 환경 변수만 `$secrets`로 쓰고, 8자 미만이면 서버가 시작하지 않는다. 입력·출력·오류를 저장하기 직전과 로그를 남기기 직전에 `***`로 바꾼다.
- **삭제:** 실행 중이면 삭제를 거부하고(409), 지우면 실행 기록도 함께 지우고 다른 워크플로우의 실패 알림 설정은 비운다.

## 정한 것

| # | 질문 | 정한 것 | 검토한 대안 |
|---|---|---|---|
| ① | 식 계산 코드 위치 | `packages/core`(M5 이후 브라우저의 식 미리보기에서도 같은 코드를 씀) | api 안에만 |
| ② | HTTP 요청 도구 | Node 내장 `fetch`(undici)에 연결 직전 IP를 검사하는 설정을 붙임 | `node:http` 직접 / 별도 라이브러리 |
| ③ | 재개 방식 | job에 heartbeat(30초)를 두고, 워커가 죽어 heartbeat가 끊기면 pg-boss가 다시 실행해 이어서 실행. 만료 시간 방식은 만료(5분 이상) 뒤에 재개하면 이미 실행 전체 제한을 넘어 바로 실패하므로 만들면서 바꿈 | 서버 시작 시 RUNNING 기록을 찾아 다시 등록 |
| ④ | 로그(pino) 도입 | 만들면서 취소. 로그의 비밀값 가리기는 Nest 기본 로거를 조금 고쳐서 하고, pino는 M10 배포 때 필요하면 도입 | 이번에 |
| ⑤ | 연습용 응답 위치 | api 안의 `/mock/*`(로그인 없이, 속도 제한 적용). `MOCK_BASE_URL`은 기본으로 api 자신 | 별도 서버 |
| ⑥ | 실행 상태 화면 | 이번에는 에디터 상단 바의 상태 글자만. 노드별 상태 색과 상세는 M5의 실행 상세 화면에서 | 이번에 캔버스에 노드별 상태 색까지 |
| ⑦ | 실행 전 저장 | 실행 버튼은 저장되지 않은 변경이 있으면 먼저 저장하고 실행(서버는 저장된 그래프로 실행) | 저장되지 않았으면 실행 버튼을 막음 |
