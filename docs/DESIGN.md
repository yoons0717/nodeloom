# 디자인 토큰

> 어두운 작업실형, 어두운 테마만 쓴다. 색은 아래 토큰(CSS 변수)으로만 쓰고 값을 코드에 직접 적지 않는다. 토큰 값은 `apps/web/src/app/globals.css`에만 있다. 밝은 테마는 토큰 값을 한 벌 더 정의하면 된다(BACKLOG). 이 문서는 코드만 봐서는 알 수 없는 규칙과 이유를 적는다. 크기·문구는 적힌 파일이 기준이다.

## 원칙

- 청록(`--accent`)은 **선택·포커스·주요 버튼·실행 중·지나간 연결선**에만 쓴다. 노드 종류, 성공, 정보 글자에는 쓰지 않는다.
- 상태는 색에만 기대지 않고 글리프(✓ 성공, ▲ 경고, ! 오류, ● 실행 중, – 건너뜀)나 글자와 함께 보여 준다.
- 목록의 실행 상태는 점 + 글자다(`features/runs/status-dot.tsx`, 카드와 실행 기록이 함께 쓴다). 색은 점에만 쓰고, 글자에 색을 넣는 건 실패뿐이다.
- `/10` 같은 투명도 색을 클래스에서 만들지 않는다. 옅은 색은 `-soft`·`-ring` 토큰을 쓴다.
- shadcn 부품이 쓰는 이름(`--primary`, `--input`, `--ring` 등)은 아래 의미 토큰을 가리키는 별칭으로만 둔다.
- 시각은 절대 시각으로 쓴다("10월 17일 12:03", 실행 기록 행처럼 날짜 묶음 안에서는 HH:mm). "2시간 전" 같은 상대 표기는 쓰지 않는다.

## 색

### 표면과 테두리

| 토큰 | 쓰는 곳 |
|---|---|
| `--bg` | 페이지와 캔버스 바탕, 입력 칸 안쪽 |
| `--surface` | 상단 바, 사이드바, 노드 목록, 설정 패널, 워크플로우 카드 |
| `--raised` | 노드 카드, 목록 항목, 버튼 |
| `--raised-hover` | 마우스를 올린 카드·버튼·목록 항목(어두운 테마라 밝아진다) |
| `--overlay` · `--overlay-hover` | 토스트, 팝오버, 툴팁, 메뉴, 확인 창(그림자와 함께) · 그 위에서 고른 메뉴·선택 목록 항목 |
| `--help` · `--help-border` · `--help-stripe` | 도움말 팝오버 바탕 · 테두리 · 규칙 표 줄무늬 |
| `--raised-open` | 도움말이 열린 노드 목록 항목 |
| `--grid` | 캔버스 점 격자 |
| `--scrim` | 드로어·확인 창 뒤 막 |
| `--border-subtle` · `--border` | 영역 사이 구분선 · 카드 등 장식 경계 |
| `--border-control` | 입력 칸·버튼 경계. `--bg`·`--surface` 위에서 3:1 이상(WCAG 1.4.11). `--raised` 위에서는 3:1이 안 되므로 raised 카드 안에는 입력 칸을 두지 않는다 |

### 글자

Tailwind에서는 `text-text-muted`처럼 이름이 겹치지 않게 shadcn 관례 이름을 쓴다.

| 토큰 | Tailwind | 쓰는 곳 |
|---|---|---|
| `--text` | `foreground` | 본문 |
| `--text-label` | `label` | 입력 칸 라벨, 보조 강조 |
| `--text-muted` | `muted-foreground` | 보조 글자(설명, 시각, 요약) |
| `--text-disabled` | `disabled` | 비활성 글자 |

### 강조와 상태

| 토큰 | 쓰는 곳 |
|---|---|
| `--accent` · `-hover` | 선택 테두리, 포커스, 주요 버튼, 실행 중 · 주요 버튼 hover |
| `--accent-soft` · `-ring` · `-glow` | 선택된 목록 행 바탕 · 선택·포커스 바깥 빛과 실행 중 점의 링 · 선을 끄는 동안 입력 포트 |
| `--success` · `-text` · `-soft` | 성공 |
| `--warning` · `-text` · `-soft` | 경고(오래 걸린 노드, 저장 안 됨) |
| `--danger` | 오류 테두리, 실패 점, 거부된 연결 미리보기 선 |
| `--danger-text` · `-soft` | 오류 글자 · 오류 배지와 위험 버튼 바탕 |
| `--danger-strong` | 연결 거부 안내, 삭제 확인 버튼 바탕(흰 글자) |

### 노드 종류와 연결선

| 토큰 | 글리프 |
|---|---|
| `--node-trigger` | ▶ |
| `--node-http` | ⇄ |
| `--node-transform` | fx (고정폭, 굵게) |
| `--node-condition` | ◇ |

노드 종류 색은 명도·채도를 맞추고 색상만 다르게 했다. 글리프 칩은 바탕에 `-soft`, 글자에 조금 밝은 `-text`를 쓴다. 연결선은 `--edge`, 실행 상세에서 지나간 선은 `--edge-active`(= `--accent`), 안 간 갈래는 `--edge-inactive` 점선이다.

## 글꼴

본문은 `--font-sans`(Noto Sans KR), 참조 키·URL·식·코드는 `--font-mono`(JetBrains Mono).

| 단계 | 크기/줄 높이 | Tailwind | 쓰는 곳 |
|---|---|---|---|
| heading | 20/28, 700 | `text-xl` | 페이지 제목 |
| title | 16/24, 700 | `text-base` | 상단 바 제목, 패널 제목 |
| body | 14/20 | `text-sm` | 본문, 입력 칸 |
| body-sm | 13/20 | `text-body-sm` | 노드 제목, 목록 행 |
| label | 12/16, 500 | `text-xs` | 라벨, 배지, 설명 |
| caption | 11/16 | `text-caption` | 노드 종류 이름, 요약 |
| glyph-sm | 9 | `text-glyph-sm` | 노드 카드 글리프 칩 안의 ▶만 |

- 시안 값을 맞추려고 단계 밖 크기를 쓸 수 있다(워크플로우 카드 이름 15/22, 카드 본문 12/18). 글자로 읽는 것은 11px보다 작게 쓰지 않는다.
- 굵기는 400·500·700만 쓰고 대문자·자간 처리는 하지 않는다.

## 모양과 간격

- 간격은 4px 격자(4·8·12·16·24·32)를 먼저 쓴다. 시안 값을 맞출 때는 6·10·14 등도 쓸 수 있다.
- 영역 안쪽 여백은 16(상단 바, 패널).
- 에디터를 뺀 화면의 본문은 왼쪽 정렬, 여백 24이고 화면 종류마다 최대 폭이 다르다: 설정 990, 목록 성격(모든 실행, 실행 기록) 1200, 워크플로우 카드 격자는 제한 없음(넓으면 칸이 늘어난다). GitLab Pajamas의 페이지 폭 규칙(설정·폼 990, 목록 1280, 보드 전체 폭)과 Supabase 디자인 시스템(설정은 좁게, 목록은 기본, 빽빽한 화면은 전체 폭)을 참고했다.
- 모서리는 4(글리프 칩, kbd) · 6(버튼, 입력 칸) · 8(노드 카드, 카드) · pill(배지).
- 조작 높이는 28 · 36 · 44. 터치에서는 누르는 영역을 44 이상으로 둔다(아래 "입력 방식").

## 부품

### 공용 (`apps/web/src/components/ui`)

| 부품 | 규칙 |
|---|---|
| Button | **default**(청록)는 화면당 하나. **outline**·**ghost**는 보조. **destructive**는 옅은 빨강(`--danger-soft`)이고, 되돌릴 수 없는 마지막 확인 버튼만 `--danger-strong` |
| Badge | `tone` = neutral·running·success·warning·danger. 글리프 ● ✓ ▲ !는 부품이 붙인다 |
| Input·Textarea·Select | 포커스는 `--accent` + `--accent-ring`, 오류는 `--danger`. 테두리가 두꺼워져도 안쪽 여백을 줄여 크기를 유지한다 |
| Field | 설명(hint)은 한 줄이고 늘 보인다. 오류는 설명 위에 따로 "! "를 붙인다. 라벨 오른쪽에 도움말 (?)를 둘 수 있다 |
| InlineError | "! 문구" 꼴 오류. 글리프는 읽지 않게(aria-hidden). 문제 목록을 함께 받을 수 있다 |
| PageHeader | 에디터를 뺀 화면의 상단 바. 뒤로 가기는 없다(사이드바가 맡음). 제목은 "맥락 / 화면"이고 좁은 화면에서는 맥락을 숨긴다 |

### 에디터와 실행 상세

| 부품 | 규칙 |
|---|---|
| 노드 카드 | 크기 고정(Condition만 더 높음)이라 캔버스 배치가 흔들리지 않는다. 선택은 `--accent` 테두리 + `--accent-ring`, 오류는 `--danger` 테두리와 "! n", 실행 중은 `--accent` 테두리와 막대, 성공은 기본 테두리와 "✓ 걸린 시간", 건너뜀은 점선·60%. 실행 상세에서는 종류 이름을 빼고 글리프만 |
| 포트 | 누르는 영역은 보이는 원보다 넓다. 선을 끄는 동안 입력 포트를 키워 강조하고, 연결할 수 없는 포트 위에서는 `--danger` 테두리 |
| 상단 바(에디터) | 이름(눌러서 편집) · 저장 상태 칩 ……… 문제 배지 · 실행. 저장하지 않은 변경이 있으면 앱 안 링크로 나가기 전에 묻는다 |
| 저장 상태 칩 | 저장 버튼을 따로 두지 않는다. 저장됨은 화면에 보이지 않는다(스크린 리더에만). 바뀌면 칩 안에 저장 버튼(⌘S), 실패하면 "다시 시도"(긴 사유는 툴팁) |
| 되돌리기·다시 하기 | 캔버스 도구 앞의 아이콘. 툴팁에 "되돌리기: 노드 삭제"처럼 동작 이름과 단축키 |
| 토스트 | 실행 버튼 아래. 성공은 저절로 닫히고 실패는 닫기 전까지 남는다 |
| 도움말 팝오버 | `features/editor/help.tsx`. 누르면 열리고 바깥을 눌러도 닫히지 않는다(× 또는 Esc, 식을 보면서 입력). (?)가 든 패널 바깥에 붙고 화살표가 (?)를 가리킨다. **식 도움말**은 노드별 설명·예시 → "식에서 쓸 수 있는 것" 표(이 부분만 스크롤) → 실행 상세 안내 순서. **노드 도움말**은 하는 일 · 다음 노드가 받는 값 · 여러 선이 들어올 때의 입력. 폭은 남은 화면 폭을 넘지 않는다 |
| 실행 상세 패널 | 위는 실행 순서(전체 시간의 절반을 넘긴 노드는 `--warning` 막대), 아래는 입력/출력 탭 · 복사 · JSON 보기, 맨 아래 고른 값을 읽는 식 |

## 사이드바

`components/app-sidebar`. 라우트 그룹 `(app)`의 모든 화면에 있고 로그인·벤치에는 없다. 화면 사이 이동은 사이드바가 맡는다.

| 항목 | 규칙 |
|---|---|
| 구성 | 머리(로고 · 접기), 워크플로우 찾기(⌘K), 전체 워크플로우 · 모든 실행(최근 24시간 실패가 있으면 danger 배지), "워크플로우" 트리(최근 수정순, 이 부분만 스크롤), 하단(새 워크플로우 · 계정 · 로그아웃) |
| 트리 | 행: 펼침 화살표 · 이름 · 오른쪽 끝 상태. 상태는 예외만 보인다: 마지막 실행이 실행 중·대기면 "● 실행 중", 아니고 최근 24시간 실패가 있으면 danger 배지("! 2"). 성공과 실행 없음은 표시하지 않는다. 이름은 편집 화면으로 가고 화살표는 펼치기만 한다. 하위 항목은 편집 · 실행 기록(24시간 실패 수, 0이면 숨김) · 설정. 지금 워크플로우는 펼쳐 둔다 |
| 활성 표시 | `--accent-soft` 바탕 + `aria-current="page"`. 실행 상세에서는 "실행 기록"이 활성 |
| 접힘 | 아이콘 + 툴팁만. 전역 메뉴와 지금 워크플로우의 하위 항목만 남는다. 선택은 쿠키(`nodeloom.sidebar.collapsed`)에 저장한다. **고른 적이 없으면 에디터에서만 접는다**(캔버스 폭) |
| 폭에 따라 | md 미만은 드로어, md – lg는 레일 + 겹쳐 열기(아래 "반응형"). md – lg의 폭은 CSS로 나누고, 펼친 저장값이면 레일과 펼친 모양을 둘 다 그려 하나만 보인다 |

| xl | ≥ 1280 | 3열(팔레트 + 캔버스 + 설정) | 나란히 | 저장값(에디터 기본 접힘) |

- 실행 기록 행은 sm(640) 미만에서 두 줄이다.
- 높이는 `dvh`/`svh`만 쓴다. `vh`는 쓰지 않는다.

### 입력 방식

- 폭(`md:` 등)으로 터치를 짐작하지 않는다. 누르는 크기와 hover는 `pointer-coarse:` / `pointer-fine:`로 나눈다.
- 터치에서 누르는 영역은 44×44 이상: 캔버스 도구 막대, 사이드바 항목, 실행 기록 거르기 칩, 노드 입출력 탭·복사, 버튼, 카드 ⋯. 보이는 크기를 그대로 둘 때는 `after:`로 영역만 넓힌다(도움말 (?), 포트).
- 누를 수 있는 버튼(`button`, `role="button"`)은 손가락 커서, 막힌 버튼(`disabled`, `aria-disabled`)은 기본 커서다(`globals.css`).
- hover 때만 보이는 버튼은 `pointer-fine:`에서만 숨긴다.
- `title=`만으로 보여 주는 정보는 없다. 문제 배지·노드 오류·저장 실패 사유는 `InfoTip`(올리기·포커스·누르기로 열림)을 쓴다.
- 터치 입력 칸은 16px(`pointer-coarse:text-base`)로 iOS 확대를 피한다. `maximum-scale`로 확대를 막지 않는다.
- HTML 끌어다 놓기는 정밀한 포인터에서만 켠다. 노드 목록은 누르면 캔버스 가운데에 추가한다.

### 겹쳐 띄우기

| 무엇 | 언제 | 규칙 |
|---|---|---|
| 드로어 | md 미만 | 왼쪽, `--scrim` 막, 포커스를 가둔다. 이동하면 닫는다 |
| 겹쳐 연 사이드바 | md – lg | 본문을 밀지 않는다. 모달이 아니다. 바깥·Esc·이동으로 닫고, 연 버튼으로 포커스를 돌려준다 |
| 설정 패널 | md – lg, 노드를 골랐을 때 | 캔버스 위 오른쪽. 바탕은 `--surface`(입력 칸 테두리 대비 3:1을 지키려고 `--overlay`를 쓰지 않음). 모달이 아니라 캔버스를 움직일 수 있다. 닫기·Esc·선택 해제로 닫힌다. 팝오버 안의 Esc는 그 팝오버만 닫는다 |
| 노드 목록 레일 팝오버 | md – lg | 레일 오른쪽, 도움말 팝오버와 같은 바탕·화살표. 이름 · 하는 일 · (?) · "+ 캔버스에 추가" |

드로어와 겹쳐 연 사이드바는 왼쪽 `env(safe-area-inset-left)`만큼 안쪽 여백을 둔다(viewport `viewportFit: 'cover'`).
